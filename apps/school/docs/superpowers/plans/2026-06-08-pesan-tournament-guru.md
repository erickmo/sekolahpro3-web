# Pesan Tournament — POV: Guru

> Design-only plan. Output of a 4-competitor design bracket judged AS a class/subject teacher.
> NOT implemented. Run `implement plan` / `full cycle` only after human approval.
> Date: 2026-06-08 · Module: Pesan · Bracket: C1 C2 │ C3 C4 → SF → FINAL

## POV brief — job-to-be-done

Guru teaches specific rombel(s)/subject(s). Job = communicate with the **wali murid of THEIR
OWN students** — academic progress, behavior, attendance follow-up ("anak tidak masuk 3
hari"), PR reminders, answer parent questions. Scoped to MY kids only, never the whole-school
public inbox. Reality: between/after teaching, on a phone; wants to reach a parent in ~2 taps
starting FROM a student or a roster, not hunt a global inbox. "Good" = pick student → message
wali, or pick rombel → broadcast, woven into the teaching surface (like Beranda "Antrean Saya"
/ Kelasku "Catatan Wali"). Pain today: `/sch/:sekolah/pesan` is a public-contact triage screen
useless for "message the wali of Budi"; the parent app is read-only so 2-way is ambiguous.

## Winner — GURU-C4 "Reimagine" (Final 40/45 · SF-B 42/45)

**Delete the inbox destination.** For a Guru, "Pesan" is the wrong noun — a teacher has no
inbox-triage job, they have a "follow up THIS kid's parent" job that is **born on the teaching
surface** (roster row, Antrean Perhatian, today's Alpa list). Turn the existing
per-student/per-class contact action into a logged, trackable **"Pesan Wali" thread** with a
2-way status lifecycle. The teacher's only list view is "Tindak Lanjut Saya" (my follow-ups
awaiting a parent reply), never a mailbox.

### Why it won (judge rationale, AS Guru)

"I never want to *open an inbox* — I want *Budi alpa 3 hari, tell his mum*, and I want to know
whether his mum answered." Verified in code: `StudentSheet.tsx` already ships one-tap "Hubungi
Wali" WA/tel deep-links; `kelas.saya.tsx` already renders the seat-roster, a "Hadir Hari Ini"
Alpa list (~L162), and a literal "Antrean Perhatian" nilai-D/remedial section (~L191). C4
upgrades the deep-link I already tap into a logged, status-tracked send with trigger context
pre-filled, gives pick-student→message AND pick-rombel→broadcast exactly where the brief asks,
scopes to MY kids, and adds the real status lifecycle + genuine 2-way (extends parent
`list_pesan`). The losing C1 models the message as a flat thread reconstructed from the
append-only Outbox queue — captures **no parent reply and no follow-up state**, the structural
heart of the job — and keeps the useless public-contact split-pane. C4's new `Pesan Wali`
doctype is Vernon-justified (native Notification is fire-and-forget, no threading/reply
capture; Email Template is content-only), reuses Mobile Outbox as-is for the gateway, and fires
a `doc_events` hook. Only concession: feasibility (heaviest build, touches the separate Frappe
repo for doctype + hook + parent reply box).

## Key screens / flows

1. **Kelas roster — inline "Kirim Pesan Wali"** (extend `StudentSheet`). Above the raw WA/tel
   deep-links, a composer with quick-template chips (Tidak masuk 3 hari / PR belum dikumpul /
   Nilai perlu perhatian / Pesan bebas). Sends in 2 taps and LOGS a thread (no more
   fire-and-forget WA). Channel WA (deep-link) or in-app.
2. **Per-rombel broadcast** — "Pesan Satu Kelas" tray in Kelasku header: one isi → every wali
   in the active seat-roster, recipient count shown before send.
3. **Tindak Lanjut Saya** — single SectionCard list of this teacher's messages still "Menunggu
   Balasan" or replied-needs-attention; read parent reply inline + re-reply. The ONLY
   thread/list view a Guru sees, scoped to MY students. Also surfaced as a Beranda Antrean Saya
   card (phase 2).
4. **Auto-suggested follow-up** — each Alpa row + Antrean Perhatian row gets a "Pesan Wali"
   button pre-filled with trigger context ("Ananda alpa 3 hari"). The message is generated by
   the academic observation, not composed cold.
