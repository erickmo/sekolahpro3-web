Perpustakaan — Manajemen Koleksi dan Sirkulasi Buku

Domain manajemen perpustakaan sekolah mencakup sirkulasi buku (peminjaman/pengembalian), pengelolaan koleksi, inventaris, pengadaan, reservasi, denda, dan laporan. Diakses melalui rute /perpustakaan dengan navigasi berbasis alur kerja harian untuk petugas sirkulasi, kepala perpustakaan, dan administrator.

Arsitektur

  • Backend: Frappe app sekolahpro (repo terpisah apps/sekolahpro). Modul perpustakaan menyediakan doctype, hook, dan whitelisted API method.
  • Frontend: Web app apps/school. Rute perpustakaan disusun di apps/school/src/routes/sch.$sekolah.perpustakaan* dengan komponen di apps/school/src/components/perpustakaan/.
  • Web routes prefix: /sch/{sekolah}/perpustakaan
  • Shared packages: @sekolahpro/api-client (Frappe resource hooks), @sekolahpro/ui (komponen design system), @sekolahpro/auth (session).
  • Pola arsitektur: Role-framed UI (peran hanya membingkai tampilan, bukan menyembunyikan akses); PageGuide per halaman; komponen visualisasi reusable; segregasi god-file (satu route, komponen, dan utilitas <300 baris).

Alur Utama

  1. Pinjam Baru: Petugas navigasi ke Peminjaman → tombol "Peminjaman Baru" → PerpCreateModal (anggota + buku + kopi + tanggal rencana) → frappe.client.insert Peminjaman Buku (draf) → auto-invalidate list.
  2. Kembalikan: List/detail Peminjaman atau detail Anggota/Buku → tombol "Kembalikan" → ReturnModal (tanggal kembali + catatan) → frappe.client.insert Pengembalian Buku → frappe.client.submit → backend on_submit runs: (a) release eksemplar, (b) generate Denda jika terlambat, (c) update Peminjaman status="Selesai", (d) promote reservasi → invalidate Peminjaman list/doc + Denda list → toast dengan total denda jika ada.
  3. Bayar Denda: List/detail Peminjaman → "Bayar Denda" row action atau section Denda → DendaDrawer (query Denda Perpustakaan by peminjaman) → "Tandai Lunas" → PATCH status_bayar="Lunas", tanggal_lunas=today → invalidate Denda list.
  4. Reservasi: Tab Reservasi → daftar queue per buku → "Reservasi Baru" modal → create Reservasi Buku → auto-sort by tanggal_reservasi asc. Return hook promote status="Dipenuhi" untuk posisi #1 jika ada eksemplar baru tersedia.
  5. Inventaris Opname: Tab Inventaris (segmented) → Stock Opname sub-tab → list draft/submit → "Buat Opname Baru" → OpnameScanPanel (barcode input, reconcile eksemplar) → tombol Submit → backend validate + update eksemplar status.
  6. Berita Acara: Tab Inventaris → Berita Acara sub-tab → "Lapor Kerusakan" → form (eksemplar + foto + kondisi) → draft → Pustakawan review di dashboard → "Approve" / "Tolak".
  7. Pengadaan: Tab Pengadaan → list pengadaan → "Pengadaan Baru" → form (sumber + vendor + item table buku+qty) → submit → backend auto-generate Eksemplar Buku N per item.
  8. Dashboard: Beranda → stats (hari ini jatuh tempo, overdue, ada denda), "Perlu Perhatian" list (BA pending, opname draft), dan visualisasi (donut status, progress ring on-time%, bar kategori, line tren 7 hari).

Navigasi Berbasis Alur Kerja

Tab diorganisir dalam grup berdasarkan alur kerja harian petugas, bukan model data:

  • Operasi Harian: Dashboard, Terminal Sirkulasi, Peminjaman, Reservasi
  • Koleksi: Katalog Buku, Kategori, Inventaris
  • Pengadaan & Anggota: Pengadaan, Anggota
  • Laporan: Laporan

Pengembalian & Denda bukan tab terpisah—per PERP-ADR-0001 keduanya adalah tampilan terfilter dari hub terpadu Peminjaman, dijangkau dari "Perlu Perhatian" di dashboard dan dari filter di hub itu sendiri.

Aturan & Kebijakan

  • Sirkulasi hub unified: Peminjaman adalah satu-satunya entry point untuk pinjam/kembali/denda. Rute lama /perpustakaan/pengembalian dan /perpustakaan/denda jadi redirect (client-side TanStack redirect).
  • Return harus melalui Pengembalian Buku: Tidak boleh db.set_value(status="Selesai") di detail peminjaman—backend hook tidak jalan, denda tidak generate, eksemplar tidak release. UI hanya menyediakan ReturnModal yang insert+submit.
  • Denda otomatis: Backend hook Pengembalian.on_submit._buat_denda_jika_terlambat (jika tanggal_kembali_aktual > tanggal_rencana_kembali). Formula: hari_terlambat = days(actual−planned), total_denda = max(0, hari_terlambat × denda_per_hari dari Pengaturan).
  • Blokir pinjam jika ada denda: Pengaturan Perpustakaan.blokir_pinjam_ada_denda → validasi Peminjaman.on_validate throw error jika anggota punya denda Belum Lunas.
  • Reservasi FIFO + promosi: Posisi antrian = count(Reservasi where buku={} and status=Aktif and tanggal_reservasi <= self.tanggal). Return hook promotes status="Dipenuhi" untuk posisi #1 ketika eksemplar baru tersedia.
  • Denormalized peminjaman di Denda: Field baru v0.6.0 diisi di hook _buat_denda_jika_terlambat dari pengembalian_buku.peminjaman. Backfill patch idempotent (skip kalau sudah ada). Menjaga konsistensi via test coverage di backend test_denda.py + test_pengembalian_buku.py.
  • Denda summary API capped: Whitelisted method sekolahpro.perpustakaan.api.denda.get_denda_summary(names: list[str], limit=100) return dict[peminjaman_name, {total_denda, status_bayar}]. List page call setelah fetch Peminjaman rows → decorateRows post-process.
  • Role framing, bukan gating: Petugas / Pustakawan / Admin peran hanya membingkai UI (PageGuide steps, ContextBar label, dashboard emphasis). Kontrol akses sesungguhnya Frappe backend. Permissive fallback: kalau peran tak terdeteksi, semua bucket granted, default primary="petugas".
  • PageGuide per halaman: Onboarding hint dibuka/tutup & status disimpan per route. Komponen PerpPageGuide render konten dari pageGuides.ts. Langkah ditag peran agar relevan untuk yang view.
  • Invalidation contract: Return submit invalidate resource:list Peminjaman Buku + resource:doc Peminjaman Buku {name} + resource:list Denda Perpustakaan. Denda mark-lunas invalidate resource:list Denda Perpustakaan.

Cross-Domain Events

Triggers (Perpustakaan memicu)

  • Pengembalian.on_submit → _kembalikan_eksemplar: Release Eksemplar Buku (status="Tersedia"), unblock anggota untuk pinjam baru (kalau Pengaturan.blokir_pinjam_ada_denda aktif).
  • Pengembalian.on_submit → _buat_denda_jika_terlambat: Insert Denda Perpustakaan jika return late. Denormalize peminjaman field.
  • Pengembalian.on_submit → _update_status_peminjaman: Set Peminjaman Buku status="Selesai".
  • Pengembalian.on_submit → _promosi_reservasi: Update Reservasi posisi #1 status="Dipenuhi" jika ada eksemplar baru tersedia untuk buku yang sama.
  • Pengadaan.on_submit → _generate_eksemplar: Insert N Eksemplar Buku per item dalam pengadaan. (PERP-ADR-0005, backend).

Listens (Perpustakaan bereaksi)

  • Tidak ada. Perpustakaan domain saat ini tidak subscribe ke event dari domain lain (Akademik, Keuangan, dll). Integrasi potensial di masa depan: Siswa create/delete trigger Anggota Perpustakaan suspend, atau Keuangan payment trigger denda mark-lunas otomatis—belum diimplementasi (YAGNI).

Batas Ruang Lingkup (YAGNI)

  • Denda multi-method payment: Hanya toggle Lunas / Diputihkan. Tidak ada cicilan, voucher, atau integrasi pembayaran (Keuangan modul). Future: daftar whitelisted method untuk auto-mark-lunas.
  • Kontrol akses fine-grain: Peran hanya framing. Otorisasi dokumen (siapa boleh submit Opname vs edit Pengadaan) dipegang Frappe default roles + custom Frappe role-based access. Tidak ada domain-level ACL.
  • Kolaborasi multi-petugas: Tidak ada lock/checkout untuk kerja paralel scan opname atau return. Async update saat ini toleran—last write wins (Frappe default). Opname session useOpnameSession.ts track lokal-saja.
  • Analytics & BI: Laporan tab punya statistik dasar (pinjam/minggu, kategori terpopuler, anggota teraktif). Tidak ada export ke data warehouse atau dashboard analytics third-party. Frappe Report API ad-hoc query saja.
  • Multi-sekolah: Rute threading sekolah param, API query filter by sekolah. Shared Pengaturan Perpustakaan per sekolah atau global—belum diputuskan (PERP-GAP-06).
  • Barcode generation/printing: Eksemplar barcode assumption sudah ada (external system / pre-printed). Scan input via TerminalScanPanel text input. Tidak ada internal barcode generator.
  • Lokasi fisik granular: Eksemplar.lokasi adalah text sederhana (Rak A, Rak B, dll). Tidak ada peta warehouse atau sistem lokasi hirarki.
