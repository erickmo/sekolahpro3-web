Absensi — Kehadiran dan Pencatatan Siswa

Sistem pencatatan kehadiran siswa, guru, dan staf terpadu dengan stasiun absensi online/offline. Mendukung kartu RFID, QR dinamis dari aplikasi siswa, dan input manual; menghasilkan ringkasan harian dan per pelajaran untuk pelaporan dan tindak lanjut.

Arsitektur

  • Backend Frappe: sekolahpro/attendance (modul baru, repo terpisah) — JWT Ed25519, pairing station, pencatatan tap, derivasi ringkasan, dispatch notifikasi.
  • Web Frontend: Route prefix /sch/$sekolah/absensi/* di sekolahpro-web/apps/school — dashboard, daftar harian, per pelajaran, guru.
  • Stasiun PWA: sekolahpro-web/apps/attendance_station (paket baru) — kiosk/tablet/perangkat guru; tap card + QR online/offline.
  • Paket bersama: @sekolahpro/api-client (resource list, field resolvers), @sekolahpro/ui (cards, modals, tables).

Doctypes / Entitas

Doctype Peran Field Kunci
Attendance Station (inferred) Perangkat terdaftar (kiosk, tablet, laptop guru) mode (gate/classroom/event), sekolah, device_fingerprint, api_key_hash, status (active/revoked)
Attendance Station Pairing (inferred) Kode satu-kali device (8 char, TTL 10 menit) code, mode, sekolah, expires_at, consumed_by_station
Attendance Card (inferred) Pemetaan UID kartu RFID/NFC → subjek (Siswa/Guru/Staff) uid (unik), subject_type, subject_id, sekolah, revoked_at
Attendance Event (inferred) Log tap mentah (audit trail), status accepted/rejected/duplicate station, subject_type, subject_id, method (card/qr/manual), direction (in/out), event_type (gate/class/event), tapped_at, jti (replay cache)
Daily Attendance Ringkasan harian per orang/hari (derivasi dari gate event, fase 7) subject_type, subject_id, date, sekolah, first_in, last_out, gate_status (hadir/terlambat/alpha)
Class Attendance Ringkasan per sesi jadwal (derivasi dari class event, fase 7) jadwal_pelajaran, date, status (hadir/izin/sakit/alpha), in_at, source (station/manual)

Absensi Guru (akademik, ada) Pencatatan kehadiran guru dan staf tanggal, guru, jam_masuk, jam_pulang, status (Hadir/Izin/Sakit/Alpa)

Alur Utama

  1. Pairing Stasiun (Fase 1): Admin jalankan start_pairing (mode/lokasi/sekolah), bagikan kode 8-char ke perangkat → device klaim dengan claim_pairing (fingerprint+pubkey) → dapatkan api_key unik.
  2. Tap Card Online (Gate/Classroom, Fase 1): Operator tap kartu RFID ke reader HID → stasiun lookup UID lokal → validasi sekolah/status → POST record_tap ke backend → backend verifikasi ulang, insert Attendance Event (accepted/rejected).
  3. Tap QR Online (Fase 3): Siswa buka "Tampilkan QR" di app → app mint JWT Ed25519 (30s TTL) via mint_qr setiap 25 detik → stasiun scan QR → verifikasi sig + exp lokal → POST ke record_tap dengan token.
  4. Offline Queue (Fase 4): Stasiun offline → tap (card/QR) masuk IndexedDB → tombol "Sinkronisasi" atau otomatis saat reconnect → flush batch dengan server → server verifikasi sig + jti dedup + timestamp skew → accept/reject dengan alasan.
  5. Derivasi Ringkasan (Fase 7): Setelah Attendance Event diterima, background job derive_summaries → upsert Daily Attendance (gate), Class Attendance (class) → hitung status hadir/terlambat/alpha; wirkan ke akademik Absensi Harian/Absensi Pelajaran.
  6. Notifikasi Wali (Fase 8): Setelah derivasi, jika event_type=gate dan wali berlangganan paid tier → dispatch push notification via notification service.

Aturan & Kebijakan

  • Sekolah Scoping: Semua entitas (station, card, event) terikat sekolah; tap lintas-sekolah ditolak dengan REJECT_CROSS_SEKOLAH.
  • Revokasi Kartu: Card dengan revoked_at != null ditolak; stasiun sinkronisasi delta setiap 5 menit.
  • Replay JTI: Setiap QR token memiliki jti unik (uuid-v7); Redis cache NX (first-write-wins) 10 menit; QR kedua ditolak REJECT_REPLAY.
  • Clock Skew: tapped_at diterima jika dalam [now-24h, now+5min]; verifikasi skew ±60s untuk exp token; exp 30s (TTL JWT).
  • Classroom Mode Binding: Guru login stasiun classroom → tap keras-terikat ke jadwal aktif mereka saat ini; tap kelas lain ditolak NO_ACTIVE_JADWAL.
  • Manual Override: Admin edit Absensi Harian/Pelajaran langsung → source flip ke manual; derivasi otomatis skip baris manual berikutnya (YAGNI: batch reconcile).
  • Derivasi Idempoten: Keyed (subject, date) untuk daily; (jadwal, subject_id) untuk class — re-run derivasi aman.
  • Anti-Spam: UID sama dalam 5s pada stasiun sama → debounce, tidak ada event.
  • Adapter Card Independen: HID keyboard, Web NFC, external bridge → masing-masing emit ke unified handler; stasiun pilih satu/beberapa saat pairing.

Cross-Domain Events

Triggers (Memicu)

  • Attendance Event accepted (Fase 7) → background job derive_summaries untuk upsert Daily/Class Attendance.
  • Daily/Class Attendance upsert (Fase 7) → derive gate_status hadir/terlambat/alpha berdasarkan jadwal sekolah jam_masuk.
  • Daily Attendance gate_status="hadir" + event_type=gate (Fase 8) → jika wali tier paid, dispatch push notification.
  • Absensi Harian/Pelajaran manually edited → set source=manual; derivasi auto skip baris ini berikutnya.

Listens (Bereaksi)

  • Daily Attendance: Bereaksi pada scheduled reconciliation (23:00, Fase 7) — rows tanpa event in → gate_status=alpha; rows expected (per jadwal) tanpa station event → gate_status=alpha (jika source≠manual).
  • Class Attendance: Bereaksi pada created/updated dengan source=station → operator tap confirm UI menampilkan ✓ + sound.
  • Siswa alpa beruntun >3 hari: Dashboard index deteksi dari Daily Attendance aggregate (Cross-domain READ).

Batas Ruang Lingkup (YAGNI)

  • Visitor/Tamu Attendance (Fase non-prioritas): Deferred — belum ada flow tamu (tidak ada Student ID card).
  • Geo-Fencing / Face Recognition (Fase non-prioritas): Deferred — fokus card + QR dulu.
  • Key Rotation + Emergency Revoke (Fase 7+): Phase 1 hanya single key "k1"; quarterly rotation + JWKS staleness handling nanti.
  • External Reader Bridge Detail (Fase 5 spike): Phase 1 placeholder; mechanism (loopback HTTP via SW vs companion process vs WebSocket) deferred.
  • Wali Subscription Doctype (Fase 8 audit): Name TBD — Phase 1 tidak create, hanya infrastructure untuk check di fase 8.
  • Batch Reconciliation via Cron (YAGNI, manual weekly audit): Tidak otomatis batch-fix missing events — admin audit Absensi Harian draft/incomplete, manual input jika perlu.
  • Master Data Cross-Check (akademik domain): Tahun Ajaran, Mapel, Kurikulum, KKM — dokumentasikan di akademik, bukan duplikasi di sini.
