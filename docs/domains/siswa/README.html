Siswa (Data Induk)

Domain manajemen data induk siswa di SekolahPro, mencakup pendaftaran, status aktif, mutasi, kelulusan, dan administrasi dokumen persetujuan serta perubahan data. Berfungsi sebagai hub data siswa yang terintegrasi dengan modul akademik, kepegawaian (wali), dan administrasi sekolah.

Arsitektur

  • Backend Frappe module: Siswa, Mutasi Siswa, Kelulusan Siswa, Perubahan Data Siswa, Persetujuan Wali, Arsip Ijazah (repo terpisah: apps/sekolahpro)
  • Web route prefix: /sch/$sekolah/siswa (tenant-scoped)
  • Package / UI shared: @sekolahpro/api-client (useResourceList, useResourceDoc, useFrappeMutation), @sekolahpro/ui (Badge, Avatar, DataTable, WorkflowStepper, ApprovalBar)
  • Pure logic layer: apps/school/src/lib/orang/ — siswaStats, nav, glossary (unit-tested, no hooks)
  • Navigation grouping: Routes organized by task intent (Ringkasan, Data Pokok, Penerimaan, Kelulusan & Keluar, Administrasi) via SISWA_NAV_GROUPS di lib/orang/nav.ts

Doctypes / Entitas

Kelulusan Siswa (inferred) Pengesahan kelulusan siswa tingkat akhir — hasil (Lulus/Tidak Lulus), no ijazah, skhun siswa, tahun_ajaran, status_kelulusan, workflow_state, no_ijazah, no_skhun, tanggal_pengesahan, melanjutkan_pendidikan

Alur Utama

  1. Pendaftaran → Siswa Aktif: Calon siswa daftar via /pendaftaran (status=Calon), TU verifikasi data via /daftar, ubah status menjadi Aktif. Kurir action queue di dashboard menunjukkan calon menunggu aktivasi.
  2. Mutasi (Naik Kelas / Pindah / DO): TU/Guru membuat record via /mutasi/new, submit → Pending Ka-TU → Pending Kepsek → Approved. Jenis mutasi: Naik Kelas (rombel change), Tinggal Kelas (repeat), Pindah Keluar (transfer out), DO (drop out). Workflow state di-track via workflow_state field; setiap approve/reject dicatat di audit trail.
  3. Kelulusan: Tingkat akhir (jenjang terakhir), TU/Guru masukkan hasil (Lulus/Tidak Lulus) via /kelulusan/new → Submit (Draft) → Pending Ka-TU approval → Pending Kepsek approval → Approved. Data hasil, no ijazah, skhun dicatat. Dashboard action queue menunjukkan pending approvals.
  4. Ijazah & Arsip: Post-approval kelulusan, ijazah diterbitkan & diarsipkan via /ijazah (Arsip Ijazah doctype). Field no_ijazah, no_skhun, tanggal_pengesahan dicatat. Dapodik sync (jika ada) adalah tanggung jawab domain Integrasi Dapodik (separate module).
  5. Persetujuan Wali (Consent): Wali grant/revoke persetujuan untuk publikasi foto, sharing data ke Dapodik, dll via /persetujuan. Status: Pending → Granted (via mobile/web) → Withdrawn/Expired. Foto siswa dikunci hingga consent granted.
  6. Perubahan Data: Request perubahan field siswa (nama, NIK, alamat, dll) via /perubahan-data/new → Draft → Pending Ka-TU → Pending Kepsek → Approved. Setiap approval step mencatat field_diubah, nilai_lama, nilai_baru di audit trail. Post-approval, nilai baru diterapkan ke Siswa master record.
  7. Wali & Rombel: /wali daftar semua wali dengan hubungan, kontak; /rombel daftar anggota rombel per tahun ajaran (read-only, edit via mutasi).

Aturan & Kebijakan

  • Status siswa: Domain nilai — Calon, Aktif, Alumni, Pindah Keluar, DO. Progression: Calon → Aktif → (Alumni | Pindah Keluar | DO). Status Aktif = siswa terdaftar dalam rombel saat ini; Calon = belum verifikasi; Pindah Keluar/DO = keluar dari sekolah.
  • Workflow approval: Kelulusan Siswa & Mutasi Siswa (jenis Pindah Keluar / DO) memerlukan multi-step approval: Draft (TU/creator) → Pending Ka-TU (review) → Pending Kepsek (final approval) → Approved atau Rejected. Rejection dihapus dan kembali Draft. Workflow dikelola via Frappe Model Workflow (backend).
  • Perubahan Data approval: Perubahan field tertentu (identitas, NIK, alamat) memerlukan approval sebelum applied. Draft disubmit → approval chain → approved values diterapkan ke Siswa record.
  • Consent requirements: Publikasi foto siswa memerlukan explicit wali grant (Persetujuan Wali, purpose=Publikasi Foto, status=Granted). Foto URL dikunci di FE (ConsentGate) jika no consent. Data Dapodik sharing juga explicit consent (purpose=Data Dapodik).
  • Dapodik submission: NISN status: Belum Diajukan → Diajukan (batch submit) → Diterbitkan (returned dari Kemendikbud) atau Ditolak. No KK wajib sebelum siswa status Aktif (Dapodik requirement). Tanggal request NISN dicatat. Sinkronisasi kelulusan & mutasi keluar ke Dapodik adalah tanggung jawab modul Integrasi Dapodik terpisah.
  • Role-based guards: Kepala Tata Usaha (Ka-TU) dapat approve mutasi/kelulusan di Pending Ka-TU; Kepala Sekolah (Kepsek) final approval di Pending Kepsek. System Manager bypass semua guards. TU operator dapat create & edit Calon/Aktif records; Guru baca-only Daftar Siswa.
  • Rombel assignment: Siswa jenjang baru (tahun masuk) masuk ke rombel initial via pendaftaran/mutasi masuk; Naik Kelas mutasi → rombel baru tahun ajaran berikutnya. Field rombel on Siswa adalah current rombel; history di Mutasi records.
  • Action queue visibility: Dashboard menampilkan items hanya saat count > 0 (Calon menunggu aktivasi, Pindah Keluar menunggu finalisasi). No fabricated stub metrics; derived strictly dari data actual.
  • PII safeguards: Field sensitif (foto, NIK, alamat, kontak wali) masked di list views. Detail akses di profil via ConsentGate (foto) & PII_ROLES (System Manager, TU, Ka-TU, Kepsek, Operator Dapodik). PII access logged via logPiiAccess untuk audit (backend integration planned).

Cross-Domain Events

Triggers (memicu)

  • Kelulusan Siswa approved: Event kelulusan.finalized dipublikasikan dengan payload (siswa, status_kelulusan, tanggal_pengesahan, jenjang). Listener di modul Integrasi Dapodik bisa menangkap event ini untuk sinkronisasi no ijazah, skhun ke Dapodik. Note: actual Dapodik sync bukan tanggung jawab Siswa domain.
  • Mutasi Pindah Keluar approved: Event mutasi.applied dipublikasikan dengan payload (siswa, jenis_mutasi, tanggal_efektif, sekolah_asal, sekolah_tujuan). Listener di modul Integrasi Dapodik bisa tangkap event untuk transfer out. Rombel sekolah asal diupdate untuk menghapus siswa dari anggota (handled dalam on_submit).
  • Mutasi Naik Kelas: Mengubah assignment Siswa.rombel untuk tahun ajaran baru, kemungkinan trigger reassignment di Penugasan Guru (guru assignment ke rombel baru).
  • Persetujuan Wali granted (publikasi foto): Unlock foto di profil siswa dan daftar siswa (FE ConsentGate removed). FotoUrl visible untuk dirender di dashboard/rapor.
  • Siswa status diubah: Event siswa.status.diubah dipublikasikan setiap kali siswa.status berubah (via mutasi, kelulusan, atau manual edit). Payload: siswa, old_status, new_status.

Listens (bereaksi)

  • Tahun Ajaran created/updated: Backend (jika hook ada) likely triggers recompute Rombel (academic domain). FE dashboard siswa menampilkan filter/segmentasi per tahun ajaran — filtering hanya, no auto-trigger tercatat.
  • Rombel membership change (dari Akademik domain): Wali Kelas view di /rombel refresh untuk tampilkan current anggota (FE list is read-only, anggota edits via mutasi/pendaftaran).
  • KKM / Kurikulum updated: Tidak directly impact Siswa records. Entri Nilai (profil akademik tab) di-render per KKM threshold untuk pass/fail assessment (Akademik domain).

Batas Ruang Lingkup (YAGNI)

  • Pembayaran Siswa doctype: Ditunda. Keuangan siswa (tagihan, pembayaran, cicilan) dikelola di domain Keuangan terpisah. Siswa profile tab Keuangan saat ini hanya stub UI.
  • Catatan Siswa doctype: Ditunda. Guru & BK notes per siswa. Modul tab Aktivitas (audit trail) ada, tapi notes structured belum di-backend.
  • Absensi Siswa & Nilai: Dikelola di domain Akademik (Entri Nilai, Absensi). Siswa profile tabs hanya menampilkan data (read-only lists dari akademik doctype).
  • Berkas/Dokumen siswa: Ditunda. Upload & versioning dokumen fisik/digital (KTP, KK, akta, rapor, sertifikat). Saat ini Dokumen list adalah stub data.
  • Mutasi masuk dari sekolah lain: Basic flow ada (Mutasi Masuk doctype + route). Detail verifikasi dokumen asal & NISN lookup via Dapodik (sekolahpro.integrasi.dapodik.verify_siswa) — implemented.
  • Pengiriman Ijazah (logistics): Ditunda. Tracking & delivery status ijazah asli post-cetak. Arsip Ijazah saat ini cuma metadata, belum ada history pengiriman.
  • Dapodik sync (Kelulusan & Mutasi): Outsourced ke modul Integrasi Dapodik terpisah. Siswa domain publishes events; Integrasi modul listens & handles sync (no Dapodik API calls dalam siswa.py).
