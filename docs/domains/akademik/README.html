Akademik — Manajemen Penilaian Operasional

Domain Akademik mengelola operasional penilaian siswa mulai dari input nilai asesmen, entri nilai per komponen, hingga penyusunan raport. Dirancang dalam tiga peran utama (Admin/Operator, Guru/Wali Kelas, Kepala Sekolah) dengan konteks periode Tahun Ajaran + Semester yang persisten dan aman dari kesalahan input periode.

Arsitektur

  • Backend Frappe module: sekolahpro.akademik (repo terpisah: sekolahpro)
  • Web routes prefix: /sch/$sekolah/akademik — operasional saja. Setup (Tahun Ajaran, Kurikulum, Mapel, KKM, Komponen Nilai, Konfigurasi) pindah ke /sch/$sekolah/master (Master Data)
  • Shared packages: @sekolahpro/api-client (resource CRUD), @sekolahpro/ui (komponen UI), @sekolahpro/auth (session & role mapping)
  • Foundation libraries:
    • lib/akademikContext.tsx — React context untuk periode (TA + Semester) + flag keamanan (isPastPeriod, noActiveTa, dirty)
    • lib/akademikPeriode.ts — Pure resolver periode (URL → localStorage → is_current → status Aktif + window → terbaru)
    • lib/akademikRole.ts — Role mapper Frappe → 3 academic buckets (admin, guru, kepala)
    • lib/akademikTrend.ts — Aggregator trend nilai per periode (sparkline data)
    • lib/predikatFromKehadiran.ts — Pure helper predikat ekstrakurikuler dari % kehadiran
  • Komponen UI: AkademikContextBar (periode selector + warning banner + guard dirty), AsesmenInput (grid input nilai autosave), EntriNilaiGrid (rekap nilai per komponen), PageGuide (panduan per-halaman), viz components (DistributionBar, HBarChart)

Alur Utama

  1. Setup Master Data (di /sch/$sekolah/master): Admin atur Tahun Ajaran (tandai is_current=1 untuk TA aktif), Mata Pelajaran, Komponen Nilai, KKM, Kurikulum, Konfigurasi.
  2. Resolusi Periode Otomatis: Saat guru buka /akademik/entri-nilai tanpa parameter, sistem resolusi chain (URL → localStorage → is_current → status Aktif + window → terbaru) memilih TA + semester, redirect URL, persist ke localStorage.
  3. Input Asesmen (Input Nilai Test): Guru pilih kelas (rombel status Aktif) & mapel → daftar test tampil → buat test baru modal (judul, tanggal, komponen, semester) → input nilai per siswa grid (autosave on-blur, validasi 0–100).
  4. Entri Nilai (Rekap Per Komponen): Guru pilih rombel/mapel/semester → editor grid nilai per siswa × komponen → grid lapor dirty ke context → autosave per baris → ringkasan simpan echo periode.
  5. Raport (Penyusunan & Cetak): Guru buka daftar raport siswa → filter per semester/TA → pilih status (Draft/Review/Submitted/Final/Locked) → cetak atau kirim ke siswa.
  6. Monitoring (Dashboard): Kepala Sekolah & Admin lihat ringkasan distribusi TA (Berjalan/Aktif/Ditutup), progres pengisian nilai, dan tren capaian akademik.

Aturan & Kebijakan

  • Satu Tahun Ajaran Aktif Per Sekolah: Field is_current=1 hanya boleh satu per sekolah. Resolusi chain gunakan is_current sebagai sinyal utama TA berjalan.
  • Periode Terbuka vs Lampau: TA dianggap "lampau/ditutup" jika status=Closed ATAU hari ini di luar [tanggal_mulai, tanggal_selesai]. Saat periode lampau, banner kuning "Anda mengedit periode lampau/ditutup" tampil untuk perhatian operator.
  • Semester Otomatis dari Window: Jika TA punya semester_ganjil_mulai/akhir dan semester_genap_mulai/akhir, sistem hitung semester dari acuan hari ini (dalam window Ganjil → "Ganjil", dalam window Genap → "Genap"). Fallback: Jul–Des → Ganjil, Jan–Jun → Genap.
  • Guard Perubahan Periode saat Dirty: Halaman entri nilai (grid) lapor status dirty via context. Saat user coba ganti periode & dirty=true, konfirmasi muncul: "Pindah periode? Perubahan belum disimpan akan hilang."
  • Validasi Asesmen Input: Nilai 0–100, kosong = belum dinilai. Autosave on-blur mengirim seluruh array nilai (Frappe ganti child rows, baris kosong di-drop). Status per-sel: idle → dirty → saving → saved | error.
  • Komponen Nilai Difilter Per Mapel: Modal "Test Baru" hanya tampil komponen yang link ke mapel terpilih.
  • Persistence Periode: URL search params ?ta=&semester= sumber kebenaran utama (shareable, bookmarkable). Perubahan sinkron ke localStorage key akademik:periode:$sekolah. Jika localStorage unavailable/corrupt, abaikan, lanjut resolusi (jangan throw).
  • Role Framing (Presentasi, Bukan Gating): Helper useAkademikRole map Frappe roles ke 3 buckets (admin, guru, kepala). UI frame label & guidance per peran; akses kontrol tetap di backend. Permissive fallback: jika session unavailable atau tak ada role cocok, grant semua peran.
  • Echo Periode di Setiap Halaman: Header operasional (entri-nilai, asesmen, raport) tampilkan periode aktif suffix (e.g., "· Periode: 2024/2025 Ganjil"). Toast simpan juga echo periode.
  • Tidak Ada TA Aktif: Resolusi jangan pernah return empty TA; fallback TA terbaru + flag noActiveTa=true. Bar tampilkan nudge info: "Belum ada Tahun Ajaran aktif — atur di Master Data" (link ke list TA). Halaman operasional tampilkan empty-state setup, bukan filter kosong.

Cross-Domain Events

Triggers (Domain Akademik memicu events lain)

  • Raport on_submit: Saat dokumen Raport di-submit, backend hook "Raport": { "on_submit": "sekolahpro.notifikasi.services.subscribers.on_raport_submit" } mengirim notifikasi (WA/email) ke siswa & wali. Domain Akademik mengeluarkan event ini; domain Notifikasi mendengarkan dan mengirim pesan.

Listens (Domain Akademik bereaksi)

Tidak ada. Domain Akademik merupakan leaf consumer dalam graph dependensi.

Batas Ruang Lingkup (YAGNI)

  • Manajemen is_current dari UI web: Tetap di Master Data backend. Fixture setup dan admin manual di Frappe desktop/mobile.
  • Periode default di modul non-Akademik: Resolusi periode hanya di Akademik. Modul lain (Absensi, Kesiswaan, Perpustakaan) yang butuh periode punya mekanisme tersendiri (atau tidak ada periode).
  • Modifikasi doctype / menambah field backend: Semua doctype (Asesmen, Entri Nilai, Raport, dll) dikelola sepenuhnya di backend Frappe. Web hanya CRUD via API.
  • Custom predikat mapping: Predikat ekstrakurikuler (Sangat Baik / Baik / Cukup / Kurang) dari % kehadiran adalah helper pure predikatFromKehadiran(). Predikat nilai akademik (A/B/C/D) adalah konfigurasi backend Frappe.
  • Laporan akademik kompleks (trend per siswa, analisis gap KKM, etc): Backend laporan Frappe atau BI tools. Web hanya dashboard ringkas + sparkline trend dasar.

Hub & Workspace

  • Hub /akademik: Kartu TA berjalan + arsip. URL ?go=kelas|jadwal|ekskul|ppdb untuk deep-link langsung ke sub-modul (auto-resolve TA aktif). Kartu PPDB next-TA untuk sekolah belum ada TA aktif.
  • Workspace /akademik/$ta: Layout ModuleShell dengan nav grup: Ringkasan (dashboard), Pengaturan (kelas), Penilaian (asesmen, entri nilai, raport), Kegiatan (jadwal, ekskul). Context bar menampilkan nama TA berjalan.
  • PPDB cross-TA: PPDB diakses via kartu di workspace dashboard (Tautan Modul), bukan di nav workspace per-TA, karena PPDB bersifat lintas-TA.
  • Absensi & Laporan cross-link: Kartu Tautan Modul di dashboard workspace juga menyediakan akses ke Absensi Harian dan Laporan Akademik (tetap di domain masing-masing).

Aturan Semester Docname

Format: TA-{tahun_awal}-{tahun_akhir_2digit}-SEM-{Ganjil|Genap}. Contoh: TA-2024-25-SEM-Ganjil. Nilai string "Ganjil" / "Genap" (bukan angka) sesuai konvensi doctype backend. Resolver lokal di lib/jadwalExport.ts.

Kelas Bebas-TA

Halaman Kelas (rombel, anggota, detail) tidak memerlukan $ta untuk query data — scoping dilakukan by-convention di backend. Param $ta hadir di URL sebagai konteks workspace tapi tidak dikirim ke API kelas.

Sidebar 21 → 16

Kelas, Jadwal, Ekstrakurikuler, dan PPDB dihapus dari ROLE_MENU_MAP sebagai pintu langsung. Koperasi cross-link dihapus (akses via kartu /pilih). Tersisa 16 grup sidebar utama di lib/menuGating.ts.
