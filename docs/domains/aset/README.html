Manajemen Aset

Modul terintegrasi untuk inventaris aset sekolah: registry master, kategori, lokasi penyimpanan, peminjaman dengan approval workflow, tiket maintenance, dan transfer antar lokasi. Kuantitatif (jumlah unit) dengan status siklus hidup (Tersedia, Maintenance, Hilang, Dihapus) dan kondisi fisik (Baik, Rusak Ringan, Rusak Berat).

Arsitektur

  • Backend Frappe App: sekolahpro.manajemen_aset (repo terpisah: sekolahpro) — modul transaksional dengan 8 doctype terdaftar di tenant registry (Sekolah-scoped), constants lintas-validator, dan 3 API layer untuk action endpoints (peminjaman, maintenance, transfer)
  • Web Routes: /sch/$sekolah/aset/* — 13 file rute Tanstack React Router (layout + list/detail sibling pattern)
  • Lib & Komponen: apps/school/src/lib/aset/ (role derivation, stats aggregation, badges, nav) + 6 komponen form modal + AsetContextBar
  • Paket Bersama: @sekolahpro/api-client (useFrappeMutation, useResourceDoc), @sekolahpro/auth (useSession), @sekolahpro/ui (Badge, Button, SearchableSelect, Tabs)

Alur Utama

  1. Inventarisasi Aset: Admin/Manajer memasukkan Aset baru (nama, kode unik per sekolah, kategori, lokasi, jumlah_total=jumlah_tersedia). Sistem guard kondisi enum, jumlah ≥ 1, kode unik.
  2. Peminjaman: Petugas/pengguna ajukan Permintaan Peminjaman (pilih aset, jumlah, peran pemohon, tanggal rencana kembali). Manajer review → setujui (reserve stok, status Dipinjam) atau tolak (notif pemohon). Saat kembali, catat jumlah_dikembalikan; jika lewat tanggal, scheduler 08:15 tandai Terlambat. Pengembalian release stok → status Dikembalikan.
  3. Maintenance: Petugas/pengguna laporkan kerusakan (Permintaan Maintenance Aset: aset, deskripsi, prioritas, jenis). Manajer jadwalkan (status Dijadwalkan, opsional assign teknisi). Teknisi mulai (status Dikerjakan; aset di-lock set_maintenance() → tidak bisa dipinjam). Selesai (clear_maintenance(), opsional catatkan biaya & kondisi baru). Status Selesai/Dibatalkan keluar dari terbuka.
  4. Transfer: Manajer buat Transfer Aset (pilih aset, lokasi asal, lokasi tujuan, catatan). Draft → selesaikan (pindahkan lokasi master aset). Perubahan lokasi tercatat di audit log.
  5. Reporting: Pengguna lihat dashboard (stat unit tersedia, aset rusak, overdue peminjaman), daftar aset dengan kondisi & status, laporan distribusi (chart status/kondisi), dan daftar peminjaman/maintenance/transfer untuk tracking status.

Aturan & Kebijakan

  • Invariant Stok: 0 ≤ jumlah_tersedia ≤ jumlah_total, dijaga via validator Aset + controller reserve()/release(). Tidak ada patch field langsung dari UI — hanya via whitelisted action endpoint.
  • Kode Unik: Kode aset & kategori & lokasi wajib unik per sekolah (enforce saat insert via assert_kode_unik_per_sekolah()). Autoname Aset = {sekolah}-{kode}.
  • Kondisi Enum (3 level): Baik (layak pakai), Rusak Ringan (perlu servis, masih pinjamable), Rusak Berat (tidak layak, kandidat penghapusan / maintenance). Set saat insert atau saat selesai maintenance.
  • Status Lock (Terkunci): Aset berstatus Maintenance/Hilang/Dihapus TIDAK boleh dipinjam (guard di reserve() → throw ValidationError). Clear via clear_maintenance() (maintenance selesai) atau admin ubah status manual.
  • Durasi Pinjam Default: Tanggal kembali rencana dihitung dari Pengaturan Manajemen Aset (maks_durasi_pinjam_aset_hari, default 7 hari). Scheduler 08:15 tandai terlambat (status Terlambat) untuk peminjaman Dipinjam lewat tanggal kembali.
  • Role-Adaptive UI: Petugas lihat aksi peminjaman/report daily, Manajer lihat approval + maintenance scheduling, Admin lihat master setup. Semua role tetap full-access backend (permissive); framing UI saja per primary role.
  • Tenant Isolation: 6 doctype (Aset, Kategori Aset, Lokasi Aset, Permintaan Peminjaman Aset, Permintaan Maintenance Aset, Transfer Aset) registered di tenant_registry.DOCTYPES["SCHOOL"]; ownership field sekolah → organisasi di-infer dari sekolah link. Read-scoped by organisasi via row-level security.

Cross-Domain Events

Triggers (memicu)

Domain Manajemen Aset tidak emit custom Frappe doc_events yang di-listen oleh domain lain (per audit codebase). Action workflow (setujui peminjaman, selesai maintenance, selesaikan transfer) memanggil method controller langsung via UI action; tidak ada async hooks ke pubsub.

Listens (bereaksi)

Domain Manajemen Aset tidak subscribe doc_events dari domain lain. Scheduler background-job (08:15 tandai_peminjaman_terlambat) adalah internal self-service, tidak cross-domain trigger.

Alasan: Domain cukup self-contained (lifecycle aset dari master → peminjaman → return/maintenance → out-of-service). Integrasi infrastruktur (Ruangan untuk lokasi, Pengguna Sekolah untuk pemohon) adalah link data statis, bukan event-driven.

Batas Ruang Lingkup (YAGNI)

  • Notifikasi Terlambat (follow-up): Pengaturan mendukung toggle notifikasi & daftar penerima, tapi implementation SMS/Email router belum; defer ke sprint berikutnya. Scheduler hanya update status Terlambat.
  • Asuransi / Garansi Aset: Tracking masa berlaku garansi tidak di-model (field tidak ada di Aset). Candidate untuk future module Aset Tracking v2.
  • Laporan Depresiasi / Kondisi Trend: Laporan sekarang hanya snapshot (distribusi kondisi/status current). Trend historis (berapa aset hilang/rusak per bulan?) belum di-track. Defer ke future analytics module.
  • Auto-Assign Teknisi: Maintenance scheduler bisa opsional isi teknisi (nama, email). Auto-matching dari job description / skill belum; admin assign manual saat jadwalkan.
  • Multi-Location Stock Allocation: Saat peminjaman, item pilih aset namun lokasi donee tidak di-filter (sistem assume aset bisa pickup dari mana saja). Future: constrain peminjaman ke lokasi terdekat pengguna atau by-intent allocation.
