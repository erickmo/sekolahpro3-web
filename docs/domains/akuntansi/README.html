Akuntansi

Modul akuntansi terpadu yang mengelola buku besar, anggaran, dan pajak Indonesia dalam satu hub. Bagian dari redesain Keuangan terpadu; backend di vernon_accounting (Frappe, repo terpisah), frontend di SkolahPro web app dengan scoping per-company (bukan per-sekolah).

Arsitektur

  • Backend: Frappe app vernon_accounting (repo terpisah) — doctype akuntansi scoped by company field, bukan sekolah. Penamaan Company mengikuti doc-id Sekolah (misal sd-aletheia-malang).
  • Frontend: Web route prefix /sch/$sekolah/akuntansi/* (34 routes) — part of unified Keuangan hub (/keuangan + /akuntansi).
  • Shared packages: @sekolahpro/api-client (useResourceList, useResourceCreate, frappeFetch), @sekolahpro/auth (useSessionStore), @sekolahpro/ui (komponen UI).
  • Company scoping: Hook useActiveCompany() dari akuntansi-scope.ts — auto-derive company dari Sekolah aktif. Utility withCompanyFilter() — inject ["company", "=", value] filter kecuali sudah ada company filter.
  • TENANT_BLOCKLIST: Semua doctype akuntansi listed di packages/api-client/src/frappeResource.ts — skip auto-inject sekolah filter (caranya, caller harus pass company filter eksplisit).

Alur Utama

  1. Setup Fondasi: Admin siapkan Fiscal Year → Accounting Period → Chart of Accounts (Account, Cost Center) → Accounting Dimension (opsional).
  2. Entry Harian: Akuntan posting Journal Entry (manual) atau Payment Entry (terima/bayar) → auto-generate GL Entry.
  3. Pajak Indonesia: Setiap bulan, kelola Tax Period → SPT Masa PPN (reconcile output/input) → e-Faktur Export (kirim ke DJP) + Withholding Tax entries (PPh 21/22/23/4(2)).
  4. Anggaran & Monitoring: Bendahara/Kepala buat Budget per tahun fiskal & cost center → Akuntan track vs realisasi GL → amend Budget jika perlu (Budget Amendment workflow).
  5. Period Close: Akuntan lock Accounting Period → submit Period Closing Voucher → freeze posting untuk periode tertutup.

Aturan & Kebijakan

  • Company Scoping: Semua doctype akuntansi harus punya company field terisi. Frontend route meng-enforce via useActiveCompany() + withCompanyFilter(). Walau Sekolah adalah unit operasional, akuntansi di-anchor ke Company agar modular (multi-tenant per company).
  • Journal Balance Rule: Journal Entry hanya bisa di-submit jika total_debit == total_credit (dalam account currency); enforced di frontend validation + backend doctype controller.
  • GL Auto-Generation: Submitting Journal Entry atau Payment Entry auto-trigger GL Entry posting via on_submit controller (Vernon backend).
  • Budget Overspend Guard: Budget Account punya overspend_action (None/Warn/Stop) — block atau warn Payment/Journal Entry jika biaya melampaui monthly budget untuk akun tertentu.
  • Tax Period Closure: Tax Period harus di-close sebelum bisa file SPT Masa; e-Faktur Export tidak bisa dilakukan sebelum dokumen jurnal/invoice final.
  • Role-Adaptive UI: Dashboard menampilkan guide per-peran (Akuntan vs Kepala); keuangan module tidak sembunyikan fitur, hanya highlight fokus. Backend Frappe tetap menjaga akses per role.
  • Multi-Currency: Journal Entry/Payment Entry support multi_currency flag; exchange rate dari Currency Exchange master; GL Entry track both account currency dan company currency.
  • Period Lock: Accounting Period bisa di-mark is_closed; sistem tidak prevent posting ke periode tertutup (guidance via UI), backend policy diatur per implementasi.
  • NPWP & Withholding: Withholding Tax Entry track supplier/customer NPWP; withholding amount dihitung dari base_amount × tax_rate; dapat di-reverse jika dokumen di-cancel.

Cross-Domain Events

Triggers (Akuntansi memicu domain lain)

Tidak ada. Akuntansi adalah modul backend-heavy; event outgoing (misal GL posting dari transaksi operasional keuangan) dikelola di level backend Vernon Accounting, bukan di sini.

Listens (Akuntansi bereaksi terhadap event dari domain lain)

Tidak ada. Akuntansi bersifat standalone — tidak subscribe ke akademik, koperasi, atau keuangan events. Keterkaitan dengan Keuangan operasional adalah UI-level (shared hub nav) bukan event/subscription.

Alasan: Scoping akuntansi per-company (bukan per-sekolah) dan ketiadaan Sekolah↔Company mapping yang fully-wired membuat event subscription lintas-tenant sulit sampai mapping clear. Integrasi backend akan dilakukan melalui direct API call atau job queue (tidak via pub/sub frontend).

Batas Ruang Lingkup (YAGNI)

  • Intercompany Transactions: Tidak ada support multi-company/consolidation dalam scope. Budget Amendment workflow approval process (workflow state: Draft → Pending Approval → Approved) ada di model tapi UI belum full implementasi.
  • Sekolah↔Company Mapping: Saat ini, admin harus ensure Company doc-id matches Sekolah name. Auto-discovery/mapping engine deferred.
  • Cash Flow Statement / Financial Reports: GL Entry ada, tapi frontend tidak render standar Neraca/Laba-Rugi/Cash Flow statements. Chart doang (DonutChart, GaugeChart di dashboard).
  • Audit Trail / Document History: Frappe native tracking (owner, creation, modified, modified_by) ada; custom audit log untuk sensitive operations deferred.
  • Period Closing Logic: Period Closing Voucher doctype ada; auto-reversing temporary account ke retained earnings tidak yet implemented.
  • Master Data Reuse: Tahun Ajaran, Mapel, KKM documented di akademik domain — tidak duplikasi di sini.
