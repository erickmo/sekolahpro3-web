Audit Log

Sistem pencatatan aktivitas append-only untuk melacak perubahan dokumen, akses pengguna, dan kejadian kritis sistem di lingkungan multi-tenant. Setiap entri tidak dapat diubah dan menyimpan konteks permintaan lengkap (request ID, session ID, trace ID) untuk investigasi keamanan dan audit kepatuhan.

Arsitektur

  • Backend Frappe module: sekolahpro.pengaturan.services.* + sekolahpro.utils.audit (in sekolahpro app)
  • Web route prefix: /sch/{sekolah}/audit → sch.$sekolah.audit.tsx (read-only list page)
  • Frontend framework: React + Tanstack Router, menggunakan komponen ResourceListPage generic
  • Shared packages: @sekolahpro/ui (Badge, DataTable, FilterBar, Pagination); @sekolahpro/api-client (useResourceList, listResource)
  • Doctype: Audit Log SekolahPro (InnoDB, tenant-scoped via sekolah field)
  • Core entry point: sekolahpro.utils.audit.log_event() + log_business_action()

Alur utama

  1. Capture on doc lifecycle: Hooks Frappe (after_insert, on_update, on_submit, on_cancel, on_trash) route doc events ke sekolahpro.utils.audit.on_doc_create/update/submit/cancel/delete().
  2. Tenant auto-population: Sebelum insert, hook auto_set_tenant (ADR-0042) menetapkan sekolah dari session tenant sehingga audit entry selalu merekam tenant owner. Audit hook berjalan SETELAH ini. (Catatan: field organisasi ada di schema tetapi tidak diset oleh writer; reserved untuk sweep tenant 2026-05-31.)
  3. Skip list check: _should_skip() menyaring Frappe internals (DocType, DocField, Role, Activity Log, dll.) dan Audit Log SekolahPro dirinya sendiri untuk menghindari infinite recursion atau noise.
  4. Diff extraction: _diff_from_doc() membandingkan _doc_before_save dengan state sekarang, menghasilkan JSON delta; dimuat ke field changes.
  5. Writer dispatch: log_event() memanggil sekolahpro.pengaturan.services.audit_writer.write() yang menjalankan redaksi (SENSITIVE_FIELD_PATTERNS), validasi reason (BR-3), dan insert dokumen dengan ignore_permissions=True.
  6. Severity resolution: Auto-derive severity dari action (Override/Delete/Cancel → warning; business verb dalam REASON_REQUIRED → warning; else info) atau gunakan explicit caller value.
  7. Request context capture: Writer menangkap request_id, session_id (W3C trace-id dari header traceparent), ip_address, user_agent untuk full observability.
  8. Business action dispatch: log_business_action() memvalidasi (doctype, action) terhadap AUDITABLE_ACTIONS matrix; enforce reason jika dalam REASON_REQUIRED; throw jika tidak auditable.
  9. Auth events: on_login() + on_logout() hooks merekam Login/Logout events tanpa reason requirement.
  10. Fail-safe semantics: Untuk STRICT_AUDIT_DOCTYPES (semua AUDITABLE_ACTIONS entries), audit insert failure propagate dan block host transaction (BR-6). Doc_event handlers gunakan best-effort (swallow error, emit SEV1 alert). Explicit calls re-throw.
  11. Archive + purge: Scheduled jobs (audit_archiver.archive_old_entries) upload entries >365 hari ke S3, set archived_at. Setelah itu, purge_after_retention() delete entries >5 tahun dengan @audit_purge_bypass flag untuk bypass DELETE trigger (BR-1).

Aturan & Kebijakan

  • Immutability (BR-1): Semua fields read-only pasca-insert. Database trigger (patches/v0_2_1/add_audit_delete_trigger.py) reject raw DELETE kecuali @audit_purge_bypass=1 flag (for retention purge only).
  • Reason enforcement (BR-3): Business action dalam REASON_REQUIRED matrix HARUS memiliki reason text non-empty. Override action wajib reason. Validation terjadi di audit_writer.write() sebelum insert. Doc_event actions (Create/Update/Submit/Cancel/Delete/Login/Logout) tidak memerlukan reason.
  • Fail-safe for sensitive doctypes (BR-6): Jika insert audit untuk STRICT_AUDIT_DOCTYPES (AUDITABLE_ACTIONS keys) gagal, exception propagate dan block host transaction. Best-effort handlers (doc_events) emit SEV1 log alert ke SekolahPro Admin recipients.
  • Redaction: Field matches SENSITIVE_FIELD_PATTERNS (password, token, secret, api_key, credit_card, cvv, dll.) di-redact jadi "***REDACTED***" di field changes JSON sebelum insert.
  • Severity auto-derive: Business verb dalam REASON_REQUIRED atau Override → warning; Delete/Cancel → warning; else info. Explicit caller severity wins.
  • Doctype skip list: _SKIP_DOCTYPES includes Frappe internals (DocType, DocField, Custom Field, Property Setter, Print Format, Report, Page, Module Def, Role, Role Permission, Communication, Version, View Log, Route History, Notification Log, Energy Point Log, Webhook Request Log) + logs (Error Log, Activity Log, Access Log, Scheduled Job Log, Email Queue, etc.) untuk reduce noise. Has Role excluded (handled by explicit grant/revoke handlers).
  • Tenant scoping (sekolah): Setiap audit entry menyimpan sekolah tenant anchor untuk multi-tenant sweep. (Field organisasi reserved tetapi belum diisi oleh writer.) Read permissions: System Manager (create/read/report/export), SekolahPro Admin (read/report), Auditor (read/report/export).
  • Role grant/revoke auditing: Has Role doctype capture grant/revoke dengan role name + user name di keterangan field. Reason wajib (BR-3). audit_reason flag pada doc diteruskan ke reason field.
  • Retention policy: Archive setelah 365 hari ke S3. Purge setelah 5 tahun (1825 hari). Scheduled tasks run daily (inferred dari archiver/exporter code patterns).
  • Login/Logout tracking: Best-effort (no reason required). Emit via on_login/on_logout hooks tanpa doc_event validation. Swallow errors, log to frappe.log_error.

Cross-Domain Events

Triggers (memicu)

  • Doc lifecycle events (all doctypes except skip list): Setiap Create/Update/Submit/Cancel/Delete pada tracked doctype → audit entry dengan action name matching + diff JSON.
  • Business actions (Entri Nilai, Raport, Transaksi Simpanan, Akad Pembiayaan, Kartu, Has Role, Pengaturan Sekolah Pro): Custom verbs (reverse, supersede, finalize, approve, restructure, writeoff, issue, block, replace, grant, revoke) via explicit log_business_action() calls di domain-specific code. See AUDITABLE_ACTIONS matrix for which (doctype, action) pairs are valid.
  • Auth events: Login/Logout via Frappe hooks (on_login, on_logout) → Login/Logout actions.
  • Override action: Explicit call to log_event(action="Override", reason=...) untuk merekam privilege escalation atau bypass (misal, admin override nilai siswa).

Listens (bereaksi)

  • Tidak ada direct listeners di Audit Log domain: Domain ini append-only, immutable, dan tidak emit events ke domains lain. Consumers (forensics, monitoring, compliance reporting) read dari Audit Log SekolahPro doctype untuk investigasi post-hoc, bukan real-time event subscription.
  • Archive/purge scheduled tasks: Inferred dari audit_archiver.py struktur, likely dipicu oleh Frappe scheduled jobs. No inter-domain event coupling.
  • SEV1 alerting (on failure): Email ke SekolahPro Admin role pada audit insert failure (intra-domain error handling, bukan inter-domain event).

Batas ruang lingkup (YAGNI)

  • Real-time alerting on suspicious patterns: Bulk-delete detector (audit_constants.BULK_DELETE_THRESHOLD=50, BULK_DELETE_WINDOW_SECONDS=60) defined dalam constants tetapi belum diintegrasikan ke live alert system di audit insert. Deferred untuk monitoring phase.
  • Audit search by content (full-text): UI support ada (searchFields di route), API support via listResource query builder, tetapi FTS indexing pada changes JSON belum didokumentasikan dan mungkin terbatas. Deferred pending query performance tuning.
  • Audit report export advanced filtering: Exporter (audit_exporter.py) code exists; UI export button ada di ResourceListPage (exportConfig interface), tetapi advanced field selection + formatting deferred.
  • Real-time audit stream (WebSocket/SSE): Not in scope; audit is historical investigation tool, not live event feed.
  • Hierarchical access control (view limited audit by role within sekolah): Current permissions (System Manager, SekolahPro Admin, Auditor) are global. Intra-school read restrictions deferred (likely ADR candidate if business requirement confirms).
