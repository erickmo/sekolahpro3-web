Pesan

Modul komunikasi internal sekolah dengan sistem inbox/outbox untuk pesan masuk dari formulir kontak publik, kanal terjadwal, serta reply inline. Hub operasional di /sch/:sekolah/pesan (school) dan /pesan (parent/student).

Hasil tournament desain (3 POV: Tata Usaha / Guru / Kepala Sekolah, lihat apps/school/docs/superpowers/plans/2026-06-08-pesan-tournament-*.md). Alur Utama

1. School Staff — Pesan Masuk & Reply

  1. List inbox: fetch Contact Inbox SekolahPro (order by creation desc, limit 100). Display grid dengan nama pengirim, preview pesan, status badge, waktu.
  2. Filter: filter by status (Baru | Dibalas | Selesai) dan search text-match (nama + email + pesan).
  3. Select pesan: klik inbox row → tampilkan detail & textarea reply di side panel kanan.
  4. Reply: tulis balasan → klik "Kirim" → insert Mobile Outbox Entry dengan op="reply_contact_inbox" + response payload (to, inbox name, body) → jika status Baru, update inbox status=Dibalas.
  5. Mark done: tombol "Tandai Semua Selesai" → batch update semua status Baru → Selesai.
  6. Refresh: invalidate query cache setelah CREATE/UPDATE.

2. Parent / Student — Inbox Read-only

  1. Fetch list: call sekolahpro.api.parent.list_pesan (requires auth, filtered per user children).
  2. Enrich: map nis → child name dari active children list untuk context.
  3. Display: list dengan judul, pengirim, isi, waktu, status dibaca (optional styling).
  4. No reply: read-only view (placeholder di student app).

3. Compose New Message (School)

  1. Staff klik "Pesan Baru" → modal dialog.
  2. Isi form: nama pengirim, email, telepon (opsional), status awal (default Baru), pesan (textarea).
  3. Validasi: nama, email, pesan wajib; email format check (HTML5).
  4. Submit → insert Contact Inbox SekolahPro → refresh list query → close modal.

Aturan & Kebijakan

  • Status workflow: Inbox dimulai Baru → dapat diubah jadi Dibalas (otomatis saat reply) → Selesai (manual atau batch mark-all). Tidak ada rollback status.
  • Reply immutability: Outbox entry bersifat append-only (queue). Tidak ada edit/delete reply.
  • Search case-insensitive: global text search pada nama, email, pesan (after HTML strip).
  • HTML stripping: backend menyimpan pesan sebagai HTML (Text Editor). Frontend strip tags untuk safe text rendering di list/detail.
  • Time format: tampil sebagai ID-IN locale (day, month abbr, HH:mm).
  • Idempotency: Outbox entries diberi unique idempotency_key (timestamp + random) untuk deduplikasi retry.
  • Parent app: pesan filtered per authenticated user (children). Jika nis=null, pesan adalah broadcast (Kepala Sekolah announcements).
  • StatCard metrics: hitung per status saat load untuk dashboard overview (Total, Baru, Dibalas, Selesai).

Cross-Domain Events

Triggers (memicu)

Tidak ada integrase event terdeteksi yang berangkat dari Pesan domain menuju domain lain dalam codebase web.

Listens (bereaksi)

Tidak ada integrase event terdeteksi yang masuk ke Pesan dari domain lain. Modul Pesan adalah self-contained: fetch & mutate Contact Inbox + Outbox, invalidate cache lokal, tidak ada hook pub/sub atau trigger ke akademik/keuangan/absensi.

Catatan: Modul ini adalah pure messaging—tidak ada sinkronisasi data dengan master akademik, evaluasi siswa, atau entri keuangan. Jika di masa depan ada skenario seperti "kirim notif otomatis saat nilai diubah", itu akan memerlukan event listener baru (belum ada).

Batas Ruang Lingkup (YAGNI)

  • Attachment support: belum ada uploader file di reply. Pesan hanya teks + metadata.
  • Conversation threads: modul saat ini list-based (flat), bukan tree/thread. Setiap inbox row adalah percakapan tunggal (asumsi 1:1).
  • Message signature: tidak ada template/footer otomatis di reply.
  • Scheduling: outbox queue asumsinya synchronous / near-real-time; belum ada delayed/scheduled send.
  • Archive / soft-delete: tidak ada fitur archive message; mark Selesai adalah proxy "resolved".
  • Two-way SMS/WhatsApp integration: outbox queue terstruktur untuk SMS/WA (response.to, op enum), tapi actual gateway integration di backend (repo terpisah).
  • Master data (Tahun Ajaran, Sekolah): sudah didokumentasikan di domain akademik/master; Pesan tidak perlu duplikasi.
