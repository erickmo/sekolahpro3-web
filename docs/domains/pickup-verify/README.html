Verifikasi Penjemputan

Sistem keamanan berbasis petugas untuk memastikan bahwa hanya orang tua atau wali yang terdaftar (dan sudah mendapat persetujuan orang tua pada tier berbayar) dapat menjemput siswa di gerbang sekolah. Autentikasi menggunakan QR code yang ditandatangani server (token jangka pendek, 30 detik) dengan fallback PIN.

Arsitektur

  • Backend: App Frappe sekolahpro (repo terpisah) — modul sekolahpro.api.pickup.* + dua doctype baru Pickup Person dan Pickup Event. Tier-gated: jika fitur pickup_realtime_notify aktif dan tier paid, event dibuat dengan status pending (menunggu persetujuan orang tua); tier free auto-approve.
  • Parent app: Rute /pickup (apps/parent/src/routes/pickup.tsx) — menampilkan QR berputar setiap 30 detik, dropdown penjemput aktif, dan daftar delegasi (tambah/edit/cabut penjemput).
  • School staff app: Rute /sch/$sekolah/pickup-verify (apps/school/src/routes/sch.$sekolah.pickup-verify.tsx) — scanner QR + form fallback PIN + kartu pelepasan siswa. Hanya terlihat untuk role Sekolah Staff atau Satpam.
  • Paket bersama: @sekolahpro/ui, @sekolahpro/api-client, @sekolahpro/auth. Parent app menggunakan qrcode.react; school app menggunakan @zxing/browser untuk pemindaian QR.

Alur Utama

  1. Setup delegasi (orang tua): Di tab "Daftar Penjemput" aplikasi parent, orang tua menambah penjemput dengan nama, hubungan, nomor telepon, dan PIN opsional (6 digit; server mencegah kode lemah seperti 123456). Sistem auto-membuat satu Pickup Person untuk orang tua sendiri pada panggilan pertama list_children.
  2. Penerbitan token QR (orang tua): Saat membuka tab "QR" atau mengubah delegasi, parent app memanggil useIssuePickupToken(nis, pickupPersonId). Backend mengembalikan token HMAC base64url yang ditandatangani (isi opak: nis, pickup_person_id, jti, exp; berakhir dalam 30 detik). Parent app me-render QR via qrcode.react dan menampilkan 6 karakter terakhir token + countdown. QR otomatis refresh saat token akan kedaluwarsa dalam <5 detik.
  3. Verifikasi di gerbang (petugas): Petugas sekolah (Sekolah Staff / Satpam) membuka rute /sch/$sekolah/pickup-verify. Dua opsi:
    • Opsi 1: Scan QR — Kamera dibuka via @zxing/browser. Saat QR terdeteksi, token dikirim ke backend via useStaffScanToken({ token, gate }). Backend memverifikasi HMAC, cek jti belum dikonsumsi, cek belum kedaluwarsa. Jika valid, buat Pickup Event dengan status=approved (free tier) atau status=pending (paid tier, tunggu orang tua).
    • Opsi 2: Fallback PIN — Petugas masukkan NIS siswa (trigger pencarian staff_list_persons_for_nis), pilih penjemput dari dropdown, masukkan PIN. Backend compare PIN dengan pin_hash bcrypt. Rate limit: 3 percobaan per 15 menit; setelah itu pin_locked. Jika cocok, buat Pickup Event dengan metode PIN.
  4. Persetujuan orang tua (paid tier saja): Jika event dibuat dengan status=pending, parent app polling list_pickup_events({ nis, since_iso }) setiap 3 detik. Kartu banner kuning menampilkan: "Penjemputan menunggu konfirmasi" + tombol "Setujui"/"Tolak". Orang tua klik → backend memanggil parent_respond_pickup({ event_id, decision }). Event flips ke approved atau declined; petugas mendapat notifikasi real-time (polling di school app setiap 2 detik atau push jika diimplementasikan).
  5. Pelepasan siswa (petugas): Setelah event approved (atau instant pada free tier), petugas melihat kartu pelepasan: foto siswa + nama + kelas, foto penjemput + nama + hubungan + telepon. Tombol "Lepaskan Siswa" + opsi "Tolak / Catat insiden" (memerlukan catatan). Klik Lepaskan → staff_complete_pickup({ event_id }) → status=completed + completed_at=now. Toast sukses, auto-reset ke scanner setelah 5 detik. Jika Tolak → staff_decline_pickup({ event_id, note }) → status=declined.

Aturan & Kebijakan

  • Autentikasi parent: Semua metode backend yang mengakses parent data (list penjemput, issue token, respond) menderivasi parent dari frappe.session.user. Parent tidak bisa pass parent ID lain; sistem selalu mengecek ownership.
  • Autentikasi petugas: Metode staff scan/verify/complete/decline memerlukan role Sekolah Staff atau Satpam. Missing role → HTTP 403.
  • Token HMAC: Server menandatangani token dengan secret PICKUP_TOKEN_SECRET (Frappe site config, never on client). Token opak base64url, tidak bisa di-parse client. Expire dalam 30 detik, single-use via jti (JWT ID) — konsumsi token catat jti, replay dalam window 30 detik ditolak dengan token_consumed.
  • PIN bcrypt: Disimpan dengan cost 12 bcrypt. Tidak pernah dikembalikan API. Rate limit: 3 percobaan per orang per 15 menit; attempt ke-4 → pin_locked. Reset PIN hanya bisa via orang tua (tidak ada unlock desk untuk staff).
  • Soft delete penjemput: Cabut penjemput set is_active=false (tidak hapus). Penjemput revoked tidak boleh dipakai untuk scan/verify baru → person_revoked error.
  • Audit lengkap: Setiap upaya scan/verify (sukses atau gagal) membuat baris Pickup Event. Gagal catat di note deskripsi error (e.g., "PIN salah attempt 1/3", "Token kedaluwarsa").
  • Tier gating: Backend baca tenant.features.includes("pickup_realtime_notify") + parent.subscription_tier (existing flag). Jika keduanya true → pending events, else auto-approve. Free tier polling parent tidak dipaksa, UI show notification banner saja jika ada event pending (untuk potential future upgrade).
  • Kode PIN lemah: Client-side dan backend tolak PIN dari set: "000000", "111111", "123456", "654321", "123123". Prevent social engineering.

Cross-Domain Events

Triggers (memicu)

  • Pickup Event dengan status=completed atau status=declined dipicu petugas. Daftar acara pelepasan ini dapat dicatat di modul keamanan atau "Riwayat Penjemputan" untuk analisa; implementasi listener tergantung roadmap keamanan fisik lain.

Listens (bereaksi)

  • Tidak ada interaksi dengan domain lain. Domain ini self-contained — entitas utama (Pickup Person, Pickup Event) hanya ref ke Siswa (existing, readonly dari perspektif pickup).

Batas Ruang Lingkup (YAGNI)

  • Notifikasi push native (Web Push API + Frappe broker) — ditunda; MVP mengandalkan polling UI + foreground app.
  • Deteksi hidup / face recognition — security theater trade-off; ditunda sampai kebutuhan organik.
  • Geofencing — hanya scan pada GPS dalam perimeter sekolah; ditunda MVP.
  • Manajemen delegasi kolaboratif multi-orang tua — ibu tambah delegate, ayah bisa lihat/edit; V1 single parent-ownership, ditunda.
  • Impor massal penjemput via CSV (untuk driver class-wide) — ditunda V2.
