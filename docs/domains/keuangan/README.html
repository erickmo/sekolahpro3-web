Keuangan (Keuangan & Akuntansi)

Domain terpadu untuk manajemen operasional keuangan harian (kas, tagihan, pembayaran, pengeluaran) dan akuntansi formal (jurnal, buku besar, anggaran, pajak) di SekolahPro. Menyediakan UI role-adaptive untuk Bendahara, Kasir, Akuntan, dan Kepala Sekolah dengan visualisasi penuh dan integrasi langsung ke doctype vernon_accounting.

Arsitektur

  • Backend: Frappe module vernon_accounting (repo terpisah) — 3 doctype baru: School Fee Invoice (Tagihan), School Expense (Pengeluaran), dan School Fee Payment (Pembayaran, derivatif Payment Entry)
  • Frontend: SekolahPro web app (apps/school) — satu hub "Keuangan" menyatukan dua route-tree: /keuangan/* (operasional, TanStack file-based) dan /akuntansi/* (accounting, 35 halaman redesain)
  • Route prefix operasional: /sch/$sekolah/keuangan → Tagihan, Pembayaran, Pengeluaran, Buku Kas, Dashboard
  • Route prefix akuntansi: /sch/$sekolah/akuntansi → Buku Besar, Anggaran, Pajak, Referensi
  • Shared packages: @sekolahpro/ui (Badge, Button, DataTable, Select, Modal), @sekolahpro/api-client (useResourceList, useResourceCreate, useResourceDoc), @sekolahpro/auth (useSession, peran Frappe)
  • Company scoping: Vernon Accounting doctypes ditenanti oleh company (bukan sekolah). Konvensi: Company doc-id sama dengan Sekolah doc-id (misal: sd-aletheia-malang). Semua rute akuntansi memanggil useActiveCompany() dari lib/akuntansi-scope.ts.

Alur utama

  1. Operasional harian Bendahara: Masuki /keuangan → lihat Dashboard (tren kas 12 bulan, realisasi vs anggaran, komposisi pengeluaran, waterfall kas) → akses Tagihan untuk issue/track SPP siswa → view Pembayaran terima → kelola Pengeluaran dengan approval chain (Draft → Approval → Disetujui/Ditolak → Dibayar) → konsultasi Buku Kas untuk arus kas harian.
  2. Operasional Kasir: Terima pembayaran via Pembayaran page → reconcile terhadap tagihan siswa → catat metode bayar (Tunai, Transfer, QRIS, Virtual Account, EDC) → lihat Buku Kas real-time.
  3. Akuntansi Akuntan: Masuki /akuntansi (terintegrasi dalam hub yang sama) → verifikasi Buku Besar (akun, jurnal, GL entries, payment rec) → planning & monitoring Anggaran (budget vs actual gauge) → kelola Pajak (PPN, PPh, e-Faktur) → atur Referensi (tahun fiskal, chart of accounts, setelan).
  4. Oversight Kepala Sekolah: Dashboard hub keuangan untuk ringkasan AR aging, budget health, cash position → approve Pengeluaran tinggi → audit via Buku Besar.
  5. Data source strategy: Tagihan & Pengeluaran live via useTagihanLive() dan usePengeluaranLive() ke vernon_accounting. Pembayaran live via usePembayaranLive(). Buku Kas derived from live data (summed by date). All scoped by useActiveCompany().

Aturan & Kebijakan

  • Peran presentasi (bukan akses): bendahara, kasir, akuntan, kepala diturunkan dari Frappe roles untuk MENEKANKAN UI (label, guidance, section visibility), tidak pernah MENYEMBUNYIKAN fitur. Akses kontrol tetap di backend (Frappe permission pada vernon_accounting doctypes).
  • Pencocokan Frappe role: Fungsi mapFrappeRolesToKeuangan() menormalisasi dan mencari substring di raw Frappe roles. Contoh: "Bendahara", "Bendahara Sekolah", "treasurer" → peran bendahara. Prioritas primary: kepala > bendahara > akuntan > kasir. Fallback permisif: tanpa sesi atau tanpa match → semua peran aktif.
  • Company scoping: Dokumen School Fee Invoice, School Expense, School Fee Payment disaring oleh company = useActiveCompany() dari session aktif (activeSekolah.name). Admin backend harus memastikan Company dengan nama sama ada untuk setiap Sekolah.
  • Akun GL balans: On submit Tagihan → Dr Piutang (AR), Cr Pendapatan. On submit Pengeluaran → posting sesuai kategori (Gaji → Expense Gaji, dll) dengan saldo debit/kredit terjaga.
  • Status workflow Pengeluaran: Draft → Approval → Disetujui/Ditolak → Dibayar (final). Pengeluaran Draft dapat diedit; setelah submit tidak boleh edit tanpa cancel-resubmit.
  • Visibilitas halaman per hub section: Operasional (Tagihan, Pembayaran, Pengeluaran, Buku Kas) menyorot bendahara/kasir; Akuntansi (Buku Besar, Anggaran, Pajak, Referensi) menyorot akuntan/kepala. Dashboard Ringkasan untuk semua. Navigasi hub (KeuanganHubNav) dipesan role via isItemEmphasized().
  • Panduan role-aware: Setiap halaman menggunakan KeuanganPageGuide dengan langkah-langkah bertingkat peran (bendahara lihat prosedur approval, kasir lihat prosedur penerimaan, dll). Storage terpisah per halaman via storageId (localStorage namespace keuangan-guide:).

Cross-Domain Events

Triggers (memicu)

  • On-submit School Fee Invoice: Trigger GL entries (Dr Piutang, Cr Pendapatan) di vernon_accounting backend. No UI event published.
  • On-submit School Expense: Trigger GL entries sesuai kategori (Gaji → Payroll Accrual, ATK → Supplies Expense, dll). No UI event published.
  • On-submit School Fee Payment: Update parent School Fee Invoice: dekremen dibayar field, update status ke "Cicilan" (jika partial) atau "Lunas" (jika full). No UI event published.

Listens (bereaksi)

  • Akademik: Keuangan membaca kelas dan tahun_ajaran dari School Fee Invoice untuk konteks halaman dan filter. Tidak ada listener aktif; join pada Student/Kelas/Tahun Ajaran di backend. Master data Tahun Ajaran, Kelas, KKM tetap di domain akademik.
  • Siswa: Keuangan membaca student field dari School Fee Invoice/Payment. Tidak ada listener; relasi di backend.
  • Koperasi / Logistik: Tidak ada integrasi langsung. Pengeluaran kategori "Kegiatan" dapat mereferensikan order koperasi secara manual via field deskripsi.

Catatan: Tidak ada event bus atau pub-sub aktif dalam domain Keuangan. Integrasi antar domain melalui foreign keys dan data read pada form load, bukan real-time updates.

Batas ruang lingkup (YAGNI)

  • Dunning & notifikasi otomatis: Kirim email reminder tagihan jatuh tempo → deferred. Notifikasi akan diimplementasikan saat email service tersedia.
  • Reconciliation engine: Match Pembayaran ke Invoice otomatis → deferred. Sekarang manual via UI (select invoice dari dropdown saat create Pembayaran).
  • Multi-currency support: Semua nilai in IDR. Multi-currency → future (enterprise).
  • Advanced tax automation: PPN, PPh, e-Faktur ditangani via form manual di halaman Pajak. Perhitungan otomatis per kategori pengeluaran → deferred.
  • Audit trail UI: Backend menyimpan changelog via Frappe versioning; UI audit-log page → deferred.
  • Budget forecasting: Proyeksi anggaran Q2-Q4 berdasarkan tren realisasi → deferred. Sekarang hanya budget vs actual per bulan.
  • Integrasi bank: Auto-import dari bank API (BCA, Mandiri, dll) → future (phase 2, memerlukan TLS & SDKs bank).
  • Buku Kas manual: Currently derived dari GL. Manual entry form untuk adjustment → deferred.
