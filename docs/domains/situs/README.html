Situs Sekolah (Website + CMS)

Per-school public website + no-code block-driven CMS. Every school gets a branded website on custom/subdomain with template selection and live content management.

Arsitektur

  • Backend module: website_sekolah (repo terpisah: sekolahpro). 11 doctypes: Template Situs, Situs Sekolah, Situs Layout Block, Situs Keunggulan, Situs Statistik, Situs Testimoni, Berita Sekolah, Halaman Situs, Agenda Sekolah, Galeri Sekolah, Prestasi Sekolah.
  • Web SPA: apps/situs (this repo). Offline-runnable demo at port 5184. Block-driven composer renders layoutBlocks from Situs Sekolah via blockRegistry.
  • CMS (Admin): apps/school routes sch.$sekolah.situs.* (this repo). Tab-based interface: Ringkasan, Tampilan (template/brand), Tata Letak (block ordering), Sorotan (child-array editors), Berita/Halaman/Agenda/Galeri/Prestasi/Domain.
  • Routes prefix: /sch/$sekolah/situs (school-admin CMS) and /situs.* for content editors (Berita/Halaman/etc.).
  • Shared packages: @sekolahpro/ui (component library), @sekolahpro/api-client (Frappe API wrapper).
  • APIs: Guest: sekolahpro.api.situs.{resolve_site, get_site, list_berita, list_agenda, list_galeri, list_prestasi, get_ppdb_info, submit_kontak, submit_pendaftaran}. Admin: sekolahpro.api.situs_admin.{get_situs, save_situs, list_template, publish, set_domain, list_konten, save_konten, delete_konten}.

Alur utama

  1. Sekolah admin masuk CMS: Buka /sch/{sekolah}/situs (ringkasan + quick links).
  2. Pilih template & brand: Tab Tampilan: pilih Template Situs (klasik/modern/ceria/aurora), set brand_color, hero_judul, hero_subjudul, hero_eyebrow, hero_cta_label/url, hero_cta2_label/url. Simpan via save_situs.
  3. Atur tata letak: Tab Tata Letak: susun blok (hero, keunggulan, statistik, testimoni, profil, berita, agenda, galeri, prestasi, ppdb, cta, kontak, richtext). Per-blok dapat dipilih variant (split/centered/fullbleed/overlay/playful untuk hero, cards/grid untuk keunggulan, dll.), toggle aktif/nonaktif, set heading override + CTA text. Simpan array layout_blocks.
  4. Kelola sorotan: Tab Sorotan: edit child-array Keunggulan (ikon emoji + judul + deskripsi), Statistik (label + nilai + satuan), Testimoni (nama + peran + foto + kutipan). Simpan per-tabel.
  5. Kelola konten: Tabs Berita/Halaman/Agenda/Galeri/Prestasi (per-sekolah CRUD via save_konten/delete_konten). Status: Draft/Terbit. Hanya Terbit rows ditampilkan publik.
  6. Atur domain: Tab Domain: set subdomain (clash-detected cross-table dengan Organisasi) atau custom_domain (verified via DNS CNAME). Gerakkan slider dari Draft → Terbit untuk publish publik.
  7. Pengunjung akses situs publik: Browser ke smp-pelita.sekolahpro.id (atau custom domain) → resolver situs.resolve_site(host) → load Situs Sekolah + Template Situs → SPA mapSite() → Composer render layoutBlocks → block registry resolve per-variant renderer (HeroBlock, KeunggulanBlock, BeritaSection, etc.) → tema tokens dari Template Situs diaplikasikan via CSS vars.

Aturan & Kebijakan

  • Tenancy: Situs Sekolah scoped to single Sekolah. Child tables (layout_blocks, keunggulan, statistik, testimoni) inherit tenant scope dari parent—tidak ada field tenant sendiri, tidak masuk tenant_registry. Subdomain uniqueness enforced cross-table vs Organisasi.
  • Status gating: Only Situs Sekolah with status=Terbit visible to guests. Draft sites resolve to null in public API.
  • Guest read security: Public reads NOT auto-scoped by permission_query_conditions. Every guest endpoint (situs.resolve_site, list_berita, etc.) explicitly filters {sekolah, status:"Terbit"} with ignore_permissions and re-checks row ownership in code.
  • PPDB anti-tamper: submit_pendaftaran asserts gelombang belongs to the resolved school before accepting registration.
  • Contact/PPDB inbox isolation: Contact Inbox & PPDB Lead (legacy) lost guest-read permission; now tenant-registered to block cross-tenant leak.
  • Template extensibility: No existing template changes when adding new template—open/closed. Provider adds Template Situs row + registers in backend constants + adds SPA blockRegistry renderer. Contract test (constant sync) prevents drift between backend TEMPLATE_KEYS and SPA.
  • Block variants: Per-block variant list locked in CMS blockSchemas.ts (mirrors SPA registry.ts). Unknown variant saved as-is (data), validated in SPA; fallback renderer prevents crash.
  • Default layout fallback: School without layout_blocks renders per-template HomeBody (backward-compat) or template's default_layout seed from fixture.
  • Role gating: CMS /situs routes gated to kepala_sekolah + admin_sekolah roles (existing gating). Guests cannot access admin APIs.

Cross-Domain Events

Triggers (memicu)

  • Situs Sekolah.save: When a school publishes (status Draft→Terbit), invalidate resolver Redis caches for host→Situs lookup. Triggered by situs_admin.publish().
  • Situs Sekolah.save: Domain verification callback (custom_domain DNS validated) → update domain_verified flag + SSL status. (Implementation pending; follows Caddy/Frappe SSL flow.)

Listens (bereaksi)

  • Pendaftaran PPDB.submit: When guest calls submit_pendaftaran, backend validates gelombang.sekolah matches resolved Situs Sekolah. Blocks cross-school PPDB submission.
  • Contact Inbox.insert: When guest submits contact form via submit_kontak, Contact Inbox row is tenant-registered (not guest-readable) to block cross-tenant data leak.

Batas ruang lingkup (YAGNI)

  • apps/landing: Global product site (sekolahpro.id marketing). Not touched; Situs Sekolah is per-school only.
  • Drag-drop visual WYSIWYG: Block order via up/down buttons (no DnD library added). Visual WYSIWYG builder deferred.
  • Server-side SEO meta injection: `vite-react-ssg` pre-renders routes (not tenants), so <meta> set client-side. Real crawler SEO needs small Caddy/Frappe server meta-injection middleware (documented as follow-up, not implemented).
  • Fasilitas block content: Fasilitas doctype not yet created; block type registered but no renderer (skip in CMS pick until content model defined).
  • Dark mode / multi-bahasa: Not in scope. Situs renders in light mode, Indonesian only (Localization module in SekolahPro is separate).
  • Berita vs News Article unification: Berita Sekolah is module-local doctype. Merger with global News Article deferred pending backend refactor.
  • Shared PPDB-wizard component: PPDB form UI in apps/situs is local. Extract to @sekolahpro/components deferred.
  • Caddy on-demand-TLS automation: Custom domain SSL provisioning can auto-request certs when domain added. Deferred pending DevOps integration.
