Jadwal Pelajaran

Mengelola jadwal pelajaran mingguan per rombel (kelas), hari libur, dan penyesuaian sementara per slot waktu atau seluruh hari tanpa mengubah data induk. Mendukung override tingkat hari (hari libur, penggantian, tambahan), dengan resolusi prioritas harian untuk KBM yang fleksibel.

Arsitektur

  • Backend Frappe module: sekolahpro.akademik (repo terpisah)
  • Web route prefix: /sch/$sekolah/jadwal (sekolahpro-web)
  • Shared packages: @sekolahpro/api-client, @sekolahpro/ui (Tabs, Badge, ResourceListPage, ResourceCreateModal)
  • Sub-modul frontend: Dashboard, Daftar Jadwal, Slot Jadwal, Jadwal Override, Slot Override

Doctypes / Entitas

Doctype Peran Field Kunci
Jadwal Pelajaran Header jadwal mingguan tetap untuk 1 rombel per semester + tahun ajaran rombel, semester, tahun_ajaran, kurikulum, is_aktif, slots (child table)
Slot Jadwal (child) 1 baris = 1 slot mingguan (hari + jam mulai/selesai + mapel + guru) hari, jam_mulai, jam_selesai, mata_pelajaran, guru, ruangan
Jadwal Override Override jadwal pada tanggal spesifik (libur, penggantian, tambahan) — prioritas tinggi dari jadwal tetap rombel, tanggal, tipe (Libur/Pengganti/Tambahan), alasan, slots (child table)
Slot Override (child) Slot pengganti dalam 1 hari override — jika tipe "Libur" maka kosong; tipe lain wajib ≥1 slot jam_mulai, jam_selesai, mata_pelajaran, guru, ruangan

Alur Utama

  1. Definisi Slot Waktu: Admin/Kepala Sekolah membuat master Slot Jadwal yang akan digunakan sebagai template pelajaran (jam pelajaran, istirahat, upacara).
  2. Susun Jadwal Mingguan: Guru/Staff Akademik membuat Jadwal Pelajaran header, mengisi rombel, semester, tahun_ajaran, kurikulum, lalu menambahkan slot per hari (hari, jam, mapel, guru).
  3. Aktifkan Jadwal: Ketika jadwal mingguan siap, set is_aktif=1. Sistem memastikan hanya 1 jadwal aktif per (rombel, semester, tahun_ajaran).
  4. Override per Hari: Untuk tanggal tertentu, buat Jadwal Override:
    • Tipe "Libur" → tidak ada KBM, slot kosong
    • Tipe "Pengganti"/"Tambahan" → wajib minimal 1 slot pengganti di child Slot Override
  5. Resolusi Harian: Sistem resolver (backend) mengecek Jadwal Override dulu untuk tanggal tertentu; jika tidak ada, fallback ke Jadwal Pelajaran aktif.

Aturan & Kebijakan

  • Unikness Jadwal Aktif: Hanya 1 jadwal aktif per kombinasi (rombel, semester, tahun_ajaran). Sebelum mengaktifkan jadwal baru, jadwal lama harus dinonaktifkan terlebih dahulu.
  • Validasi Jam Slot: Setiap slot: jam_selesai > jam_mulai (sanity check).
  • Pencegahan Overlap Kelas: Tidak boleh ada 2 slot rombel yang sama dengan jam overlap pada hari yang sama dalam 1 jadwal mingguan.
  • Pencegahan Overlap Guru (Internal): Satu guru tidak boleh punya 2 slot overlap di hari yang sama dalam jadwal yang sama.
  • Pencegahan Overlap Guru (Silang Jadwal): Guru tidak boleh dijadwalkan dengan jam overlap di 2 rombel berbeda pada tahun + semester yang sama (konflik lintas jadwal aktif).
  • Pencegahan Konflik Kelas (Silang Jadwal): Rombel tidak boleh punya 2 jadwal aktif dengan slot overlap (safety-net).
  • Validasi Override per Tipe:
    • Tipe "Libur" → slots harus kosong (tidak ada KBM)
    • Tipe "Pengganti"/"Tambahan" → slots wajib minimal 1 baris
  • Unikness Override: Hanya 1 override per (rombel, tanggal). Tanggal tidak boleh duplikat.
  • Pencegahan Overlap Guru (Override): Guru tidak boleh bentrok jam di 2 override berbeda pada tanggal yang sama.
  • Tenant Scoping (ADR-0042): Field sekolah adalah tenant owner; organisasi adalah anchor (fetch dari sekolah).
  • Role-Based Access:
    • System Manager: Full CRUD
    • Pegawai Guru: Read-only (lihat jadwal untuk persiapan KBM)

Keamanan & Validasi

  • Validasi Konflk Guru: Backend menjalankan Jadwal Override._validasi_konflik_silang() saat insert/update untuk mendeteksi guru bentrok jam di 2 override berbeda pada tanggal yang sama, atau vs jadwal aktif. Raised ValidationError jika conflict ditemukan.
  • Cascading Validation: Saat Jadwal Pelajaran diaktifkan (is_aktif=1), sistem scan semua slot untuk memastikan tidak ada overlap kelas/guru. Validasi ini dilakukan di jadwal_pelajaran.validate_and_activate().
  • Data Integrity Tenancy: Setiap doctype di domain ini (Jadwal Pelajaran, Jadwal Override, Slot Jadwal, Slot Override) mempunyai field sekolah (tenant owner) dan organisasi (anchor dari sekolah). Query otomatis di-filter per sekolah aktif pengguna.
  • Audit Trail: Frappe track_changes otomatis di-enable untuk semua doctype domain ini. Perubahan header (rombel, is_aktif, tipe) dan child table dicatat dengan user + timestamp.
  • No Client-Side Trust: Semua validasi konflik (overlap guru, jam slot, duplicate override) dijalankan di server backend, bukan di frontend. Frontend hanya display + UX hint.

Cross-Domain Events

Triggers (memicu)

  • Jadwal Pelajaran save (is_aktif=1): Bisa memicu alert atau notifikasi ke modul Penugasan Guru untuk verifikasi bahwa semua guru dalam slot sudah punya SK Mengajar aktif.
  • Jadwal Override insert: Bisa memicu alert/notifikasi ke Absensi Guru jika tipe "Libur" (hari non-KBM, guru tidak perlu masuk), atau jika tipe "Pengganti" (guru berubah, perlu update presensi).
  • Slot guru atau mapel berubah: Potensial impact ke Entri Nilai (nilai siswa terkait mapel) dan Absensi Pelajaran (presensi per pelajaran).

Listens (bereaksi)

  • Dari Penugasan Guru: Ketika SK Mengajar guru dihapus atau di-nonaktifkan, dashboard Jadwal bisa menampilkan alert bahwa guru sudah tidak berhak mengajar (kontrol preventif di Jadwal Override/penggantian).
  • Dari Absensi Guru: Dashboard Jadwal menerima info guru izin → dashboard menampilkan alert "Guru Izin → Kelas Terdampak" (stub untuk future linking ke fitur cari pengganti).
  • Dari Konfigurasi Tahun Ajaran/Semester: Ketika semester ditutup atau tahun ajaran aktif berubah, jadwal non-aktif semester lama tidak lagi dijadwalkan, dan filter di frontend otomatis switch ke tahun/semester aktif baru.

Batas Ruang Lingkup (YAGNI)

  • Jadwal per-rombel saja (per 2026-06-03): Tidak ada dukungan jadwal by-guru (guru pribadi mengambil kelas ad-hoc). Guru dijadwalkan melalui Penugasan Guru yang di-assign ke rombel.
  • Template Slot Jadwal (master) masih dalam desain: Fitur "copy-paste" slot dari template belum diimplementasikan. Saat ini slot diisi manual per jadwal.
  • Konflik ruangan: Tidak ada pencegahan overlap ruangan (2 rombel di ruangan sama jam yang sama). Kontrol ini ditangguhkan per fitur pengaturan fasilitas & room scheduling v2.
  • Bulk edit slot: Fitur edit batch slot (mis. shift semua jam +30 menit) belum ada; direncanakan post-v1.
  • Export/Import jadwal: Belum ada fitur import dari file Excel atau export ke format ical. Ditangguhkan post-v1.
  • Historisasi perubahan jadwal: Tracking perubahan slot (audit log detail) tidak tersedia per 2026-06-03; sistem hanya track `modified` header. Detail historisasi ditangguhkan v2.
  • Integrasi Sistem Informasi Sekolah (real-time): Sinkronisasi dua-arah dengan sistem SIS pihak ketiga tidak ada; hanya fallback ke Frappe REST API standar.

Fase 1 — Satu Pintu Akademik (2026-06-11)

Rute Jadwal dipindah ke bawah workspace Akademik per-TA. Akses langsung via sidebar dihapus.

  • Rute baru: /sch/$sekolah/akademik/$ta/jadwal/* (13 rute: index, daftar, daftar.$name, papan, agenda, slot, slot.$name, slot-override, override, permintaan, persetujuan, kotak, pantauan)
  • Rute lama: /sch/$sekolah/jadwal/* — stub redirect (sch.$sekolah.jadwal.index.tsx + sch.$sekolah.jadwal.$.tsx) redirect ke hub /akademik?go=jadwal.
  • Semester docname lokal: Format TA-{tahun_awal}-{tahun_akhir_2digit}-SEM-{Ganjil|Genap}, e.g. TA-2024-25-SEM-Ganjil. Nilai "Ganjil"/"Genap" sesuai konvensi doctype backend.
  • Nav grup Kegiatan: Jadwal masuk grup Kegiatan di workspace nav (bersama Ekskul).
  • Absensi ModuleFlow cross-link: Rute /sch/$sekolah/jadwal/daftar di AbsensiFlow (stub-redirect convention) tetap valid — stub redirect ke rute baru di runtime.
