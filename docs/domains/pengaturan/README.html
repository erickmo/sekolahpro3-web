Domain Pengaturan

Mengelola konfigurasi tenant sekolah meliputi identitas institusi, akademik, peran pengguna, integrasi, notifikasi, keamanan, billing, dan branding. Dashboard komprehensif yang disesuaikan dengan peran, dilengkapi dengan audit trail.

Arsitektur

  • Backend Frappe Module: sekolahpro.pengaturan (repo terpisah: sekolahpro). Doctypes: Feature Flag, Modul Aktif, Sekolah, Organisasi, Tahun Ajaran, Semester.
  • Web Route Prefix: /sch/$sekolah/pengaturan (tenant-scoped). Layout wrapper mengelola tab navigasi.
  • Frontend Pages: sch.$sekolah.pengaturan.index (dashboard utama 9 tab), sch.$sekolah.pengaturan.modul (list modul aktif), sch.$sekolah.pengaturan.feature-flag (list feature flag dengan toggle inline).
  • Packages Shared: @sekolahpro/ui (Tabs, SectionCard, DataTable, Modal, etc.), @sekolahpro/api-client (useResourceList, useResourceDoc, useResourceDelete), @sekolahpro/auth (useSession untuk gating role).
  • Data Scoping: Feature Flag dan Modul Aktif adalah doctypes global (tidak per-sekolah), namun dikontrol oleh master data yang berada di blokir global (TENANT_BLOCKLIST).

Doctypes / Entitas

Doctype Peran Field Kunci
Feature Flag Gating fitur per tenant via flag boolean + rollout % + audience filter key (unique), enabled (checkbox), rollout_pct (0–100), audience_json (roles, sites filter)
Modul Aktif (child table) Toggle modul per tenant; child dari Organisasi nama_modul (select: Akademik, Keuangan, Kepegawaian, Asrama, Kurikulum Pesantren, Perpustakaan, Kesehatan, Ekstrakurikuler), aktif (checkbox default=1)
Sekolah Identitas institusi primer nama, npsn, nsm, jenis (TK/SD/SMP/SMA/SMK/Ma'had/Lainnya), status, akreditasi

Tahun Ajaran Academic calendar; parent dari Semester nama, sekolah, tanggal_mulai, tanggal_selesai, aktif, status
Semester Child dari Tahun Ajaran nama, tahun_ajaran, tanggal_mulai, tanggal_selesai, status

Alur Utama

  1. Load Pengaturan Index: Route /sch/$sekolah/pengaturan/ render PengaturanPage. Komponen wrapper (sch.$sekolah.pengaturan.tsx) menampilkan tab navigasi utama (Umum, Modul Aktif, Feature Flag) dan menghitung badge count menggunakan useResourceList dengan filter aktif.
  2. View Tab Modul Aktif: Route /sch/$sekolah/pengaturan/modul memanggil MasterResourcePage dengan doctype="Modul Aktif". Menampilkan tabel dengan inline toggle (InlineToggle component) untuk mengaktifkan/menonaktifkan modul per baris.
  3. View Tab Feature Flag: Route /sch/$sekolah/pengaturan/feature-flag memanggil MasterResourcePage dengan doctype="Feature Flag". Inline toggle untuk enabled field.
  4. Detail Modul/Flag: Click pada row menuju /sch/$sekolah/pengaturan/modul/$name atau feature-flag/$name. MasterDetailPage menampilkan read-only fields + edit modal (MODUL_FIELDS / FEATURE_FLAG_FIELDS).
  5. Dashboard Sekolah Tab: Tab "Sekolah" di index menampilkan 3 sections: Identitas Sekolah, Alamat & Kontak, Domain & Tenant. Tab "Akademik" menampilkan Tahun Ajaran Aktif, Skala Penilaian, Jam Operasional. Tab "Peran" untuk manajemen peran pengguna. Tab "Integrasi" menampilkan status koneksi eksternal. Tab "Notifikasi" untuk preferensi channel. Tab "Keamanan" untuk kebijakan password, autentikasi, audit. Tab "Billing" untuk paket dan tagihan. Tab "Branding" untuk logo dan warna. Tab "Log Konfigurasi" untuk riwayat perubahan.
  6. Toggle Inline & Save: Klik toggle pada Modul/Feature Flag → InlineToggle component memanggil updateResourceDoc via API → revalidate cache → badge update otomatis.

Aturan & Kebijakan

  • Feature Flag Gating: Backend menggunakan is_enabled(key: str, user: str | None) dari sekolahpro.utils.feature_flags. Evaluasi: cek DB → enabled=False → False; audience filter (roles/sites) → jika no match → False; rollout_pct >= 100 → True; rollout_pct <= 0 → False; else stable hash bucket < rollout_pct → True. Cache TTL 60s per flag.
  • Modul Aktif Scope: Modul Aktif adalah child table dalam Organisasi doctype. Setiap organisasi (tenant) memiliki daftar modul aktif sendiri. Frontend hanya toggle aktif/nonaktif per modul per tenant.
  • Role-Based Access: Edit Identitas Sekolah hanya untuk roles: SekolahPro Admin, SekolahPro Manager, System Manager. Lainnya read-only. Feature Flag list hanya readable oleh SekolahPro Admin + System Manager; full CRUD hanya System Manager. Modul Aktif: System Manager full CRUD; others read-only.
  • Tenant Scoping: Dashboard per sekolah via param $sekolah. Data yang ditampilkan disesuaikan dengan sekolah aktif, kecuali Feature Flag dan Modul Aktif yang global tetapi difilter per tenant konteks.
  • Audit Log: Tab "Log Konfigurasi" menampilkan riwayat perubahan (aktor, aksi, waktu, tone). Data dalam component state; integrasi actual audit log dengan backend bisa melalui new API endpoint GET /api/resource/audit-log atau sejenisnya.
  • Export Konfigurasi: Button di PageHeader mengekspor semua settings sebagai JSON file (client-side download).
  • Global vs Per-Tenant: Feature Flag dan Modul Aktif adalah master data global (tidak per-sekolah dalam DB), namun gating/enablement logic dapat mempertimbangkan konteks tenant via audience_json (roles/sites filter).

Cross-Domain Events

Triggers (memicu)

  • Feature Flag Change (Pengaturan → Mobile PWA / Backend Features): Saat Feature Flag row di-update (enabled/rollout_pct berubah), pada_update hook memanggil invalidate_cache(key). Backend route dapat menggunakan flag state untuk gating akses fitur. Mobile/Backend ensure_enabled() memanggil is_enabled(key); jika false → fitur disabled.
  • Modul Aktif Change (Pengaturan → Akademik / Keuangan / dll): Saat modul di-toggle di Organisasi, frontend bisa dispatch event ke akademik/keuangan modules untuk enable/disable UI sections atau backend endpoints. Implementasi actual event dispatcher belum terintegrasi; saat ini hanya toggle state lokal.

Listens (bereaksi)

  • Dari Akademik (Tahun Ajaran / Semester): Pengaturan dashboard menampilkan Tahun Ajaran Aktif + Skala Penilaian (KKM). Saat akademik domain mengubah tahun ajaran, Pengaturan tab akademik perlu refresh tahun state. Implementasi: polling via useResourceDoc atau webhook.
  • Dari Integrasi (Dapodik / EMIS / Payment Gateway): Status koneksi integrasi (Terhubung/Belum/Error) ditampilkan di tab Integrasi. Saat backend integrasi sync selesai, status berubah + timestamp terakhir_sinkron update. Frontend dapat mendengarkan via polling atau server-sent event.
  • Dari Auth / User Management: Saat user role berubah, Pengaturan badge dan access control perlu refresh. Tidak ada event eksplisit; saat ini rely pada session state dan role cache.

Batas Ruang Lingkup (YAGNI)

  • Advanced Audience Targeting: Feature Flag audience_json mendukung roles + sites filter; tidak ada filter per user, per IP, per geography, atau per custom attribute. Deferred untuk fase rollout lebih lanjut.
  • Dependency Management: Jika modul A memerlukan modul B aktif, tidak ada validasi atau blocking. Deferred untuk rule engine dedicated.
  • Scheduled Flag Rollout: Rollout % manual; tidak ada scheduled gradual rollout (mis. 10% hari 1 → 50% hari 7). Deferred.
  • SSO / SAML Config UI: Keamanan tab menyediakan field SSO (dropdown), tetapi form actual setup SAML config belum di-implement. Deferred ke authentication domain.
  • Backup Restore UI: Keamanan tab menampilkan "Backup Otomatis" status + retensi, tetapi restore wizard belum ada. Deferred.
  • Real-time Collab Sync: Tidak ada live collaboration untuk edit pengaturan (mis. dua admin edit bersamaan). Deferred.
  • Wizard Onboarding Pengaturan Umum: Dashboard menampilkan semua tab; tidak ada guided wizard untuk setup awal tenant. Wizard hanya ada untuk PPDB setup (route terpisah). Deferred untuk pengaturan sekolah.
