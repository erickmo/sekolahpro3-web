Kelas & Rombel — Pengelompokan & Manajemen Siswa Akademik

Domain Kelas & Rombel mengelola pengelompokan siswa akademik mulai dari pembentukan rombongan belajar, penugasan wali kelas, manajemen daftar siswa per rombel, hingga monitoring kapasitas dan kondisi kelas. Menyediakan dashboard operasional dan alur setup struktural dari pembentukan rombel hingga penjadwalan mata pelajaran.

Arsitektur

  • Backend Frappe module: sekolahpro.siswa (repo terpisah: sekolahpro) — doctypes Rombongan Belajar, Anggota Rombel
  • Web routes prefix: /sch/$sekolah/kelas — dashboard, daftar kelas, rombongan belajar, anggota rombel, detail kelas per $kodeKelas
  • Shared packages: @sekolahpro/api-client (resource CRUD dengan Frappe REST), @sekolahpro/ui (komponen UI modular), @sekolahpro/auth (session & role mapping)
  • Foundation data files:
    • apps/school/src/data/kelas.ts — mock data generator untuk development (siswa, guru, jadwal, nilai, absensi)
    • apps/school/src/lib/glossary.ts — definisi istilah akademik (Rombel, PPDB, TA, NIS, NIP)
  • Komponen UI domain: components/kelas/RombelFormModal (create/edit rombel), components/kelas/AnggotaRombelFormModal (manage anggota), components/ResourceListPage (generic list CRUD)

Alur Utama

  1. Setup Rombel: Admin/Tata Usaha membuat Rombongan Belajar dengan nama, tahun ajaran, jenjang, tingkat, kapasitas, dan ruangan. Controller validasi kapasitas>0, tingkat dalam range 1–12, status enum valid.
  2. Penugasan Wali Kelas: Tata Usaha menunjuk User (role Wali Kelas/Guru) ke field wali_kelas di rombel. Dashboard menampilkan warning "Rombel Tanpa Wali Kelas" untuk follow-up.
  3. Enrollment Siswa: Tata Usaha menambah Siswa ke rombel via tab Anggota Rombel. Controller Pendaftaran Siswa (domain siswa) menambah row Anggota Rombel + recount jumlah_siswa saat siswa lulus PPDB. Validasi: siswa tidak boleh Aktif dua kali dalam satu rombel (spec rule 4).
  4. Monitoring Kapasitas: Dashboard otomatis menghitung stat: rombel tanpa wali, rombel >100% kapasitas, rombel penuh (jumlah_siswa >= kapasitas), rombel tanpa jadwal aktif. Attention list highlight masalah.
  5. Penjadwalan: User navigasi dari dashboard ke modul Jadwal Pelajaran (/sch/$sekolah/jadwal/daftar) untuk set jadwal per rombel. Dashboard warn jika rombel aktif belum ada jadwal aktif.
  6. Detail Kelas: Wali kelas / admin akses kelas detail (/sch/$sekolah/kelas/$kodeKelas) melihat roster siswa, jadwal mapel, rekap nilai, absensi, jurnal kelas, aktivitas audit log. Tab-based interface (Ringkasan, Siswa, Jadwal, Nilai, Absensi, Jurnal, Aktivitas).

Aturan & Kebijakan

  • Kapasitas enforcement: Rombongan Belajar harus kapasitas > 0. Validasi di on_submit + recount_jumlah_siswa() alert (non-throwing) jika aktif anggota > kapasitas pasca-mutasi.
  • Grade-level bounds: Tingkat harus 1–12 (SD 1–6, SMP 7–9, SMA 10–12). Defensive guard di Rombongan Belajar._validate_tingkat().
  • Unique active enrollment (spec rule 4): Satu siswa tidak boleh Aktif lebih dari satu kali dalam satu Rombongan Belajar. Anggota lama yang keluar (status=Keluar) tidak memblok re-enrolment. Validasi di Rombongan Belajar._validate_unique_anggota().
  • Denormalization: jumlah_siswa: Count of Aktif anggota disimpan di field read-only jumlah_siswa. Diupdate oleh recount_jumlah_siswa() setelah insert/delete/update anggota (dijalankan dari Pendaftaran Siswa, Mutasi Siswa, Kelulusan Siswa).
  • Status rombel: Select: Aktif (siap pembelajaran), Ditutup (archived/tidak aktif). Validasi enum di controller.
  • Role-based access: System Manager, Tata Usaha — full CRUD; Kepala Sekolah — read-only; Wali Kelas — read saja; Pegawai Guru — read saja.
  • Tenant scoping: organisasi field (read-only, fetch dari sekolah.organisasi) anchor rombel ke organisasi utama untuk multi-tenant query filtering.
  • Dashboard alerts: "Tanpa Wali Kelas" (critical), ">100% Kapasitas" (critical), "Penuh" (warning), "Tanpa Jadwal Aktif" (warning) — link aksi cepat ke form yang bisa di-edit.

Cross-Domain Events

Triggers (memicu)

  • Rombongan Belajar.on_insert / after_insert: Set jumlah_siswa = 0 (denorm initial count). Tenant scoping organisasi fetch dari sekolah.organisasi.
  • Anggota Rombel.validate(): Per-row checks (status enum, no_urut > 0 jika set). Trigger sebelum Rombongan Belajar.validate().
  • Rombongan Belajar.validate(): Cross-row checks: unique_anggota, kapasitas_vs_anggota, tingkat range, status enum.

Listens (bereaksi)

  • Pendaftaran Siswa (domain siswa).on_submit(): Menambah row ke Anggota Rombel child table + call rombel.recount_jumlah_siswa() → db_set("jumlah_siswa", count) tanpa re-validate.
  • Mutasi Siswa.on_submit(): Update status anggota dari Aktif → Keluar (mutasi keluar) atau insert baru (mutasi masuk) + recount. Detail di spec siswa.
  • Kelulusan Siswa.on_submit(): Update status anggota → Keluar (siswa lulus) + recount.
  • Web dashboard kelas (/sch/$sekolah/kelas): Query "Rombongan Belajar" + "Jadwal Pelajaran" untuk compute attention items. Jika rombel aktif tanpa jadwal is_aktif=1 maka warning "Tanpa Jadwal".

Batas Ruang Lingkup (YAGNI)

  • Nilai siswa per mapel: Deferred ke domain akademik (Entri Nilai, Asesmen, Raport). Kelas detail page menampilkan mock/linked data setelah BE siap.
  • Absensi harian & rekapan: Deferred ke domain akademik (Absensi Pelajaran, Absensi Harian). Dashboard kelas menampilkan % kehadiran mock. Join dengan actual data via Absensi doctype post-sprint.
  • Jurnal kelas & aktivitas: Mock data di kelas.ts. Audit Log SekolahPro doctype (backend) akan supply real action history post-integration.
  • Perpindahan rombel dalam tahun ajaran: Tidak support. Siswa assign ke rombel sekali per tahun via Pendaftaran. Mutasi keluar = siswa keluar sistem, tidak re-assign rombel lain.
  • Konfigurasi kapasitas default per Unit Jenjang: Hardcoded 32 di Rombongan Belajar JSON. Future: inherit dari Unit Jenjang.default_kapasitas (YAGNI).
  • Role permissions granular per rombel: Not implemented. Wali Kelas role read-only semua rombel. Future: scope wali kelas ke rombel-nya saja (low priority, low ROI).
