# SaaS Login Gaps — Design Spec

- **Date:** 2026-06-02
- **Status:** Implemented (merged `origin/main` `cb7e44c`)
- **Domain:** auth / provider console (frontend `apps/saas`)
- **Task size:** M (~8 files; new test infra + 1 new route/page + 2 edits to `login.tsx` + tests)
- **Base branch:** `main`
- **Builds on:** SaaS login single-panel redesign `b775aec` (this spec closes its gaps)

## Problem

The SaaS login redesign (`b775aec`) shipped a single-panel centered login but left four gaps:

1. **No tests at all.** `apps/saas` had zero test infrastructure — no `vitest.config.ts`, no `@testing-library`, no jsdom. Its `test` script was `vitest run --passWithNoTests`. The redesign added real UI logic (show/hide password, submit, error handling, busy state) with nothing guarding it. Violates the Vernon test gate.
2. **`/403` is a dead link.** `__root.tsx` wraps the whole console in `RequireAuth roles={["SekolahPro Admin"]}`. A user who authenticates but lacks that role is sent by `RequireAuth` to `/403` — a route that did not exist, so the router fell through to its not-found handler instead of an explanatory page.
3. **No redirect for an already-authenticated visitor.** `__root.tsx` renders `<Outlet/>` for `/login` without a session check, so a signed-in user navigating back to `/login` saw a redundant form.
4. **No autofocus.** The username field was not focused on load.

## Approach

### G1 — Test infrastructure + coverage

Mirror `apps/school`'s setup, not a bespoke one:

- `vitest.config.ts` — `environment: "jsdom"`, `globals: false`, `setupFiles: ["./vitest.setup.ts"]`.
- `vitest.setup.ts` — `import "@testing-library/jest-dom/vitest"`.
- devDeps — `@testing-library/{react,jest-dom,user-event}`, `jsdom`.
- `login.test.tsx` (7) + `403.test.tsx` (2). `globals:false` → each file owns `afterEach(cleanup)`.

Route components are tested by **exporting the Page function** from the route file and rendering it directly, mocking `@tanstack/react-router` (keeping `createFileRoute` real via `importOriginal` spread) and `@sekolahpro/auth`. This is the established repo pattern.

> **Decision — assertions, not jest-dom matchers.** `toHaveTextContent`/`toBeDisabled` fail `tsc --noEmit` (TS2339): the vitest `Assertion` augmentation comes from the side-effect import in `vitest.setup.ts`, but the app tsconfig is `include:["src"]` and the setup file sits outside `src/`, so tsc never sees the augmentation. Use plain assertions (`el.textContent.toContain(...)`, `(btn as HTMLButtonElement).disabled`), matching `apps/school`. Logged as `.wolf/buglog` `bug-021`.

### G2 — `/403` route

New `apps/saas/src/routes/403.tsx` exporting `ForbiddenPage` + `Route` for `/403`. Explains the missing `SekolahPro Admin` role and offers a sign-out (`logout()` → navigate `/login`) to switch accounts. `routeTree.gen.ts` is gitignored and regenerated by the TanStack router plugin on `vite build`/`dev`, so no manual route-tree edit.

### G3 — redirect already-authenticated

`LoginPage` reads `useSession()`; when `status === "authenticated"` it returns `<Navigate to="/" />` before rendering the form (early return placed **after** all hooks to respect rules-of-hooks). Handled in the route component rather than `__root.tsx` to avoid adding a conditional hook to `Layout`.

### G4 — autofocus

`autoFocus` on the username `Input`.

## Decisions / rationale

- **Guard in the route, not the root.** Keeps `Layout`'s hook order stable and the redirect testable in isolation.
- **Mirror `school` test setup** over inventing config — one monorepo testing convention.
- **No "forgot password" link** — this is an internal provider/admin console; account recovery is an admin-platform concern, out of scope here.
